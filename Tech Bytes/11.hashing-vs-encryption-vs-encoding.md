# Hashing vs Encryption vs Encoding (Stop Mixing Them Up!)

> Encoding transforms data for transport (no secret), Encryption hides data so it can be unlocked later (needs a key), and Hashing creates a one-way fingerprint that can never be reversed.

## What You'll Learn

- The exact difference between **Encoding**, **Encryption**, and **Hashing**
- Why **Base64** is NOT encryption
- Why passwords must be **hashed + salted** (never encrypted)
- Why fast hashes like `MD5` and `SHA-256` are bad for passwords (and what to use instead)
- A quick cheat sheet for picking the right tool for any job

---

## The Quick Comparison

| Property | Encoding | Encryption | Hashing |
| :--- | :--- | :--- | :--- |
| **Goal** | Compatibility / safe transport | Confidentiality (secrecy) | Integrity / verification |
| **Reversible?** | Yes — by anyone | Yes — only with the secret key | **No** (one-way) |
| **Requires a Key?** | No | Yes (symmetric or asymmetric) | No (except HMAC) |
| **Output Size** | Grows with input size | Grows with input size | Fixed length (e.g. 256 bits) |
| **Examples** | Base64, URL encoding, UTF-8 | AES-256, ChaCha20, RSA | SHA-256, bcrypt, Argon2 |

---

## 1. Encoding (For Transport, Zero Security)

**Encoding** converts data from one format into another using a **publicly known algorithm** so systems can safely transmit or store it.

- **Base64** turns binary data (like an image) into safe ASCII text (`SGVsbG8=` → `Hello`).
- **URL Encoding** turns spaces and special characters into `%20`, `%3F`, etc.

> [!CAUTION]
> **Base64 is NOT security!** Anyone can decode a Base64 string in one second. Never use Base64 to "hide" API keys, passwords, or sensitive URLs.

---

## 2. Encryption (Two-Way Secret Scrambling)

**Encryption** scrambles readable **plaintext** into unreadable **ciphertext** using a secret **key**, so that authorized parties with the key can decrypt it back later.

- **Symmetric (AES-256, ChaCha20):** Same key locks and unlocks. Used for encrypting database disks, files, and HTTPS traffic.
- **Asymmetric (RSA, ECC):** Public key locks, private key unlocks. Used for TLS handshakes, SSH keys, and digital signatures.

Use encryption whenever you **need to get the original data back** (e.g., credit card numbers, private messages, API secrets at rest).

---

## 3. Hashing (One-Way Digital Fingerprint)

**Hashing** runs any input (a word or a 10 GB video) through a mathematical function to produce a **fixed-length fingerprint (digest)**:

- **Deterministic:** Same input always produces the exact same hash.
- **Avalanche Effect:** Changing a single bit in the input produces a completely different hash.
- **One-Way:** You cannot mathematically reverse a hash back to the original input.

### Storing Passwords Safely: Salt + Slow Hash

Never store passwords in plaintext — and **never encrypt them** either (if an attacker steals your database and encryption key, every password is exposed). Instead, **hash** them:

1. **Add a unique random Salt** per user before hashing — so two users with the same password (`password123`) get completely different hashes, defeating precomputed **Rainbow Tables**.
2. **Use a deliberately SLOW password hash** like **Argon2id**, **bcrypt**, or **scrypt**.

Why not `SHA-256` for passwords? Because `SHA-256` is designed to be **ultra-fast** — a modern GPU can guess billions of `SHA-256` passwords per second! **Argon2id** and **bcrypt** are intentionally slow and memory-hard, turning brute-force attacks from seconds into centuries.

## Decision Cheat Sheet

| Use Case | What to Use |
| :--- | :--- |
| **Sending binary data inside JSON/email** | Encoding (`Base64`) |
| **Verifying a downloaded file wasn't corrupted** | Fast Cryptographic Hash (`SHA-256`) |
| **Storing user passwords in a database** | Salted Slow Password Hash (`Argon2id` or `bcrypt`) |
| **Protecting private messages or files at rest** | Encryption (`AES-256-GCM`) |
| **Verifying a webhook came from Stripe/GitHub** | Keyed Hash (`HMAC-SHA256`) |

## Summary

| Technique | Analogy |
| :--- | :--- |
| **Encoding** | Translating English into Morse code — anyone with the chart can read it |
| **Encryption** | Locking a letter in a safe — only someone with the key can open it |
| **Hashing** | Turning potatoes into hash browns — you can verify it came from potatoes, but you can never turn it back into a potato |
