# Why 0.1 + 0.2 !== 0.3 in Programming

> Computers store numbers in base-2 (binary), and just like `1/3` repeats forever in base-10 (`0.3333...`), simple decimals like `0.1` repeat forever in binary.

## What You'll Learn

- Why `0.1 + 0.2` evaluates to `0.30000000000000004`
- How base-10 vs base-2 fractions behave
- How IEEE 754 floating-point numbers store decimals in memory
- Why you should never use `float` or `double` for money
- Practical ways to handle decimal math accurately in Java, JavaScript, and Python

---

## The Famous Surprise

Open almost any programming language and run `0.1 + 0.2`:

```java
public class FloatDemo {
    public static void main(String[] args) {
        System.out.println(0.1 + 0.2);          // 0.30000000000000004
        System.out.println(0.1 + 0.2 == 0.3);   // false
    }
}
```

```javascript
console.log(0.1 + 0.2);        // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false
```

This is **not** a bug in Java, JavaScript, or Python. It is a fundamental consequence of how binary arithmetic works.

## Base-10 vs Base-2 Fractions

In **base-10 (decimal)**, a fraction terminates cleanly only if its denominator's prime factors are `2` and `5` (the prime factors of `10`):

- `1/2 = 0.5` (terminates)
- `1/5 = 0.2` (terminates)
- `1/3 = 0.3333333...` (repeats forever)

In **base-2 (binary)**, the only prime factor of `2` is `2`. So a fraction terminates cleanly **only if its denominator is a power of 2** (`1/2`, `1/4`, `1/8`, `1/16`, ...):

| Fraction | Decimal (Base-10) | Binary (Base-2) | Exact in Binary? |
| :--- | :--- | :--- | :--- |
| **1/2** | `0.5` | `0.1` | Yes |
| **1/4** | `0.25` | `0.01` | Yes |
| **1/10** | `0.1` | `0.00011001100110011...` | No (repeats forever) |
| **1/5** | `0.2` | `0.00110011001100110...` | No (repeats forever) |

Because a computer has finite memory, it has to **round** the repeating binary digits after 53 bits of precision (for a 64-bit `double`). When you add the two tiny rounding errors of `0.1` and `0.2` together, the leftover error becomes visible as `0.30000000000000004`.

## How IEEE 754 Stores a 64-Bit `double`

Almost all modern CPUs follow the **IEEE 754** standard. A 64-bit `double` splits its 64 bits into three parts:

| Part | Bits | Role |
| :--- | :--- | :--- |
| **Sign** | 1 bit | `0` for positive, `1` for negative |
| **Exponent** | 11 bits | Scales the number up or down (powers of 2) |
| **Mantissa (Significand)** | 52 bits | Stores the precision digits |

This gives `double` a massive range (up to ~`1.8 × 10^308`) with about **15–17 significant decimal digits** of precision — great for graphics, physics, and scientific math, but risky for exact decimal equality.

## How to Handle It Properly

### 1. Comparing Floats — Use an Epsilon (Tolerance)

Never compare floating-point results with `==`. Instead, check whether the difference is smaller than a tiny threshold (`epsilon`):

```java
double a = 0.1 + 0.2;
double b = 0.3;
double epsilon = 1e-9;

boolean isEqual = Math.abs(a - b) < epsilon; // true
```

### 2. Money & Financial Calculations — Use Integers or `BigDecimal`

> [!WARNING]
> Never store currency amounts in `float` or `double`. Tiny rounding errors compound across thousands of transactions and cause audit failures.

Two battle-tested approaches for money:

- **Store in the smallest unit (cents/paise)** as a `long` integer (e.g. `$19.99` → `1999`). Integer addition and subtraction are 100% exact.
- **Use `BigDecimal` (Java) or `Decimal` (Python)** — always pass a `String` to the constructor, not a `double`:

```java
import java.math.BigDecimal;

// Good: exact decimal representation
BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
System.out.println(a.add(b)); // 0.3

// Bad: passes the already-inaccurate double into BigDecimal
BigDecimal bad = new BigDecimal(0.1);
System.out.println(bad); // 0.1000000000000000055511151231257827021181583404541015625
```

## Summary

| Concept | Key Takeaway |
| :--- | :--- |
| **Root Cause** | `0.1` and `0.2` are repeating fractions in base-2 binary |
| **Standard** | IEEE 754 stores floats with 1 sign bit, 11 exponent bits, and 52 mantissa bits (`double`) |
| **Equality Check** | Use `Math.abs(a - b) < epsilon` instead of `==` |
| **Money / Exact Math** | Store integer cents (`long`) or use `BigDecimal("0.1")` with string constructors |
