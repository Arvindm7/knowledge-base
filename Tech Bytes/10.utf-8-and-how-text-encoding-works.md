# ASCII, Unicode, and UTF-8 — How Computers Store Text and Emojis

> Computers only understand numbers (`0`s and `1`s). Unicode assigns every character and emoji on Earth a unique number (code point), and UTF-8 is the clever variable-length recipe that turns those numbers into bytes without breaking legacy ASCII.

## What You'll Learn

- Why **ASCII** wasn't enough for a global internet
- The difference between **Unicode (Code Points)** and **Encodings (UTF-8, UTF-16)**
- How **UTF-8** fits English text in 1 byte and emojis in 4 bytes
- Why `"👨‍👩‍👧‍👦".length` returns `11` in JavaScript and Java

---

## 1. ASCII: The Original 128 Characters (1963)

Early computers used **ASCII**, which mapped **7 bits** (`0` to `127`) to English letters, digits, punctuation, and control characters:

- `'A'` = `65` (`01000001`)
- `'a'` = `97` (`01100001`)
- `'0'` = `48` (`00110000`)

ASCII worked great for English — and terribly for everyone else (Hindi, Japanese, Arabic, accented European letters, math symbols, and emojis didn't exist in ASCII). For years, different countries invented incompatible code pages, causing garbled text called **mojibake** (`Ã©` instead of `é`).

---

## 2. Unicode: One Universal Number Per Character

**Unicode** solved the chaos by creating one giant universal table that assigns every character in human history a unique number called a **Code Point** (written `U+XXXX`):

| Character | Unicode Code Point | Name |
| :--- | :--- | :--- |
| `A` | `U+0041` | Latin Capital Letter A |
| `é` | `U+00E9` | Latin Small Letter E with Acute |
| `अ` | `U+0905` | Devanagari Letter A |
| `€` | `U+20AC` | Euro Sign |
| `🚀` | `U+1F680` | Rocket |

**Key distinction:** Unicode only defines the *number* for each character. How that number is stored as bytes on disk or sent over the network is the job of a **character encoding** (like UTF-8 or UTF-16).

---

## 3. UTF-8: The Genius Encoding That Won the Web

Created in 1992 by **Ken Thompson** and **Rob Pike** (on a diner placemat!), **UTF-8** encodes Unicode code points using **1 to 4 bytes**:

| Code Point Range | Bytes Used | Binary Pattern | Examples |
| :--- | :--- | :--- | :--- |
| `U+0000` – `U+007F` | **1 byte** | `0xxxxxxx` | All ASCII (`A`, `z`, `0`, `?`) |
| `U+0080` – `U+07FF` | **2 bytes** | `110xxxxx 10xxxxxx` | `é`, `ñ`, Greek, Cyrillic, Arabic |
| `U+0800` – `U+FFFF` | **3 bytes** | `1110xxxx 10xxxxxx 10xxxxxx` | `अ`, `€`, Chinese/Japanese/Korean |
| `U+10000` – `U+10FFFF` | **4 bytes** | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` | `🚀`, `😀`, rare historical scripts |

### Why UTF-8 Won

1. **100% backward-compatible with ASCII:** Any valid ASCII file is already a valid UTF-8 file, byte for byte!
2. **Self-synchronizing:** Every continuation byte starts with `10`, so even if you jump into the middle of a stream, you immediately know where the next character starts.
3. **Space-efficient:** English/code/HTML stays 1 byte per character (unlike UTF-32, which wastes 4 bytes on every single letter).

## 4. Why Emoji String Lengths Are Weird!

Try running this in JavaScript or Java:

```javascript
console.log("A".length);       // 1
console.log("🚀".length);      // 2  (Wait, what?!)
console.log("👨‍👩‍👧‍👦".length); // 11 (Wait, WHAT?!)
```

Two things cause this:

1. **UTF-16 Surrogate Pairs:** Both Java and JavaScript store strings internally as **UTF-16** (16-bit units). Characters above `U+FFFF` (like `🚀`) don't fit in 16 bits, so they take **two** 16-bit code units (a *surrogate pair*).
2. **Zero-Width Joiners (ZWJ):** Complex emojis like `👨‍👩‍👧‍👦` are actually **4 separate emojis** (`👨`, `👩`, `👧`, `👦`) glued together with invisible **Zero-Width Joiner** (`U+200D`) characters!
   - `4 emojis × 2 code units + 3 ZWJ × 1 code unit = 11`!

> [!WARNING]
> Never slice a string with `.substring(0, 10)` blindly if it might contain emojis — you can split a surrogate pair in half and produce a broken `` character!

## Summary

| Term | Meaning |
| :--- | :--- |
| **ASCII** | Legacy 7-bit table of 128 English characters |
| **Unicode** | Universal catalog mapping every character/emoji to a unique **code point** (`U+XXXX`) |
| **UTF-8** | Variable-length encoding (1–4 bytes), backward-compatible with ASCII, standard on the web |
| **UTF-16** | Internal string format in Java and JS; emojis take 2+ code units (and ZWJ sequences take even more) |
