# How File Compression Works (ZIP, GZIP, and Why You Can't Zip a JPEG Twice)

> Compression shrinks files by removing redundancy — either **losslessly** (reconstructing every exact bit, like ZIP) or **lossily** (quietly discarding details human eyes and ears barely notice, like JPEG and MP3).

## What You'll Learn

- The difference between **Lossless** and **Lossy** compression
- Three classic lossless tricks: **Run-Length Encoding**, **Huffman Coding**, and **LZ77**
- How `ZIP` and `GZIP` combine them (DEFLATE)
- Why zipping a `.jpg`, `.mp4`, or `.zip` file barely shrinks it (or makes it bigger!)

---

## Lossless vs Lossy Compression

| Type | Exact Original Recovered? | Typical Compression Ratio | Common Formats |
| :--- | :--- | :--- | :--- |
| **Lossless** | Yes — 100% bit-for-bit identical | 2× – 10× | `ZIP`, `GZIP`, `PNG`, `FLAC`, `Brotli`, `Zstd` |
| **Lossy** | No — permanently drops minor details | 10× – 100× | `JPEG`, `WebP`, `MP3`, `AAC`, `MP4 (H.264/AV1)` |

- You **must** use lossless compression for code, text, executables, and databases (losing even 1 bit corrupts them).
- You can use lossy compression for photos, audio, and video because human perception ignores high-frequency colors and sounds masked by louder ones.

## Three Clever Tricks Behind Lossless Compression

### 1. Run-Length Encoding (RLE)

Replace repeating sequences with `(count, value)`:

```text
Original:   WWWWWWWWWWWWBWWWWWWWWWWWWBBBWWWWWWWWWWWWWWWWWWWWWWWWB
Compressed: 12W1B12W3B24W1B
```

Simple and super effective for images with large solid-color regions (like icons or fax scans), terrible for random text.

### 2. Huffman Coding (Shorter Codes for Common Symbols)

In normal ASCII, every letter costs **8 bits** — whether it's the super common `'e'` or the rare `'z'`.

**Huffman coding** builds a frequency tree and assigns **short bit codes** (e.g. 2–3 bits) to frequent characters and **longer bit codes** to rare characters — just like Morse code gives `E` a single dot (`.`) and `Q` four symbols (`--.-`).

### 3. LZ77 (Back-References to Repeated Phrases)

Instead of repeating a phrase that appeared earlier in the file, **LZ77** replaces it with a tiny pointer `(go back X bytes, copy Y bytes)`:

```text
Original:   "the cat sat on the mat"
Compressed: "the cat sat on (back 15, len 4)mat"
```

### How ZIP & GZIP Work: DEFLATE

Both `ZIP` and `GZIP` (used by almost every website to compress HTML/CSS/JS over HTTP) use **DEFLATE**, which simply runs **LZ77 first** (removing repeated phrases) and **Huffman coding second** (shrinking the remaining symbols).

## Why You Can't Compress a File Forever

Ever tried zipping a `.jpg`, `.mp4`, or an already-zipped `.zip` file and noticed the new `.zip` is actually **slightly larger**?

Two mathematical reasons explain this:

1. **Entropy (Information Theory):** Compression works by exploiting *patterns and repetition*. Already-compressed files have had almost all redundancy stripped out, so their bytes look nearly random — leaving no patterns left to shrink.
2. **The Pigeonhole Principle:** There are fewer short bit-strings than long bit-strings. No lossless algorithm can shrink *every* possible input — for every file it shrinks, there must be other random-looking files that get slightly bigger (due to the compression header overhead).

> [!TIP]
> Modern web servers prefer **Brotli (`br`)** or **Zstandard (`zstd`)** over `GZIP` — they achieve ~15–25% smaller text payloads for HTML, CSS, and JavaScript at fast decompression speeds.

## Summary

| Concept | Key Takeaway |
| :--- | :--- |
| **Lossless** | Zero data loss (`ZIP`, `GZIP`, `PNG`, `Brotli`) — required for text & code |
| **Lossy** | Drops imperceptible details (`JPEG`, `MP3`, `MP4`) for massive space savings |
| **DEFLATE** | `LZ77` (back-references) + `Huffman Coding` (shorter codes for frequent bytes) |
| **Entropy Limit** | Already-compressed or encrypted data looks random and cannot be compressed further |
