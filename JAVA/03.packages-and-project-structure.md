## What is a Package?

A **package** in Java is a way to **group related classes and interfaces** together. Think of it as a folder on your computer — it organises files so they are easy to find and don't clash with each other.

### Why Do Packages Exist?

Without packages, every class in your project would live in one flat list. Imagine having hundreds of classes — finding anything would be a nightmare, and two classes with the same name would collide.

Packages solve three problems:

1. **Organisation** — Related classes live together (e.g., all database classes in `com.myapp.database`)
2. **Name collision prevention** — Two classes named `User` can exist in different packages (`com.myapp.model.User` and `com.otherapp.model.User`)
3. **Access control** — Some classes and methods can be made visible only within their own package

---

## Creating a Package

To place a class inside a package, add a `package` declaration as the **very first line** of your `.java` file:

```java
package com.myapp.greetings;

public class Hello {
    public void sayHello() {
        System.out.println("Hello from com.myapp.greetings!");
    }
}
```

### Rules for the `package` Statement

- It must be the **first non-comment line** in the file
- Only **one** `package` statement is allowed per file
- The package name must match the **folder structure** on disk

So the file above must be saved at:

```text
com/myapp/greetings/Hello.java
```

If the folder path does not match the package name, the compiler will throw an error.

### Package Naming Conventions

| Convention | Example |
| :--- | :--- |
| **All lowercase** | `com.myapp.utils` |
| **Reverse domain name** | `com.google.auth`, `org.apache.commons` |
| **Dot-separated hierarchy** | `com.company.project.module` |

Companies use their reversed domain name as the base to ensure globally unique package names.

---

## The Default Package

If you do **not** write a `package` statement, your class belongs to the **default package** (also called the unnamed package).

```java
// No package declaration — this class is in the default package
public class QuickTest {
    public static void main(String[] args) {
        System.out.println("I'm in the default package");
    }
}
```

> [!WARNING]
> The default package is fine for quick experiments, but **never use it in real projects**. Classes in the default package cannot be imported by classes in named packages, and it makes your code impossible to organise as it grows.

## The `import` Statement

When you want to use a class from another package, you need to **import** it.

### Importing a Single Class

```java
import java.util.Scanner;

public class InputDemo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.println("Enter your name:");
        String name = sc.nextLine();
        System.out.println("Hello, " + name);
        sc.close();
    }
}
```

Here, `Scanner` lives in the `java.util` package. Without the `import`, Java would not know where to find it.

### Importing All Classes from a Package

Use the wildcard `*` to import every class in a package:

```java
import java.util.*;
```

This imports `Scanner`, `ArrayList`, `HashMap`, and every other class in `java.util`.

> [!NOTE]
> The wildcard `*` only imports classes from that exact package. It does **not** import sub-packages. For example, `import java.util.*` does **not** import classes from `java.util.stream`.

### Fully Qualified Name (No Import Needed)

Instead of importing, you can use the full package path directly:

```java
public class NoImportDemo {
    public static void main(String[] args) {
        java.util.Scanner sc = new java.util.Scanner(System.in);
        int num = sc.nextInt();
        System.out.println("You entered: " + num);
        sc.close();
    }
}
```

This is verbose and rarely used, but it is helpful when two imported classes have the same name.

### Resolving Name Conflicts

If two packages each have a class with the same name, you must use the fully qualified name for at least one:

```java
import java.util.Date;

public class DateConflict {
    public static void main(String[] args) {
        Date utilDate = new Date();                       // java.util.Date
        java.sql.Date sqlDate = new java.sql.Date(0L);   // java.sql.Date

        System.out.println("util.Date: " + utilDate);
        System.out.println("sql.Date: " + sqlDate);
    }
}
```

### Static Imports

You can import **static members** (methods and fields) of a class so you can use them without the class name:

```java
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;

public class StaticImportDemo {
    public static void main(String[] args) {
        double radius = 5.0;
        double area = PI * radius * radius;  // No need to write Math.PI
        double root = sqrt(25);              // No need to write Math.sqrt(25)

        System.out.println("Area: " + area);
        System.out.println("Square root of 25: " + root);
    }
}
```

## Java Project Folder Structure

A well-organised Java project follows a standard folder layout. Here is a typical structure:

```text
my-java-project/
├── src/                          ← All source code lives here
│   └── com/
│       └── myapp/
│           ├── Main.java         ← Entry point (com.myapp.Main)
│           ├── model/
│           │   ├── User.java     ← com.myapp.model.User
│           │   └── Product.java  ← com.myapp.model.Product
│           ├── service/
│           │   ├── UserService.java
│           │   └── ProductService.java
│           └── util/
│               └── StringHelper.java
├── bin/                          ← Compiled .class files go here
├── lib/                          ← External JAR libraries
└── README.md
```

### Explanation of Each Folder

| Folder | Purpose |
| :--- | :--- |
| **`src/`** | Contains all `.java` source files, organised by package |
| **`bin/`** or **`out/`** | Contains compiled `.class` bytecode files |
| **`lib/`** | Holds third-party JAR files your project depends on |
| **`model/`** | Classes that represent data (also called entities, POJOs, or DTOs) |
| **`service/`** | Classes that contain business logic |
| **`util/`** | Helper/utility classes with reusable methods |

### How the Folder Maps to the Package

The folder path under `src/` directly mirrors the package name:

```text
File path:    src/com/myapp/model/User.java
Package:      com.myapp.model
Class:        User
Full name:    com.myapp.model.User
```

This one-to-one mapping is **mandatory** — Java enforces it at compile time.

## Compiling and Running with Packages

### Step 1: Write the Code

Create a file at `src/com/myapp/Main.java`:

```java
package com.myapp;

import com.myapp.model.User;

public class Main {
    public static void main(String[] args) {
        User user = new User("Alice", 25);
        System.out.println(user);
    }
}
```

Create a file at `src/com/myapp/model/User.java`:

```java
package com.myapp.model;

public class User {
    private String name;
    private int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return name + " (age " + age + ")";
    }
}
```

### Step 2: Compile

From the project root directory, compile all files and put the output in `bin/`:

```text
javac -d bin src/com/myapp/Main.java src/com/myapp/model/User.java
```

- `-d bin` tells the compiler to place `.class` files in the `bin/` directory
- The compiler automatically creates the matching folder structure inside `bin/`

After compilation, `bin/` looks like this:

```text
bin/
└── com/
    └── myapp/
        ├── Main.class
        └── model/
            └── User.class
```

### Step 3: Run

Run the program by specifying the **classpath** and the **fully qualified class name**:

```text
java -cp bin com.myapp.Main
```

Output:

```text
Alice (age 25)
```

### What is the Classpath?

The **classpath** tells the JVM where to look for `.class` files. It can include:

- Directories (e.g., `bin/`)
- JAR files (e.g., `lib/gson-2.10.jar`)
- Multiple paths separated by `;` on Windows or `:` on Linux/Mac

```text
java -cp bin;lib/gson-2.10.jar com.myapp.Main
```

## Access Modifiers and Packages

Java has four access levels. Two of them are directly related to packages:

| Modifier | Same Class | Same Package | Subclass (other package) | Everywhere |
| :--- | :---: | :---: | :---: | :---: |
| **`public`** | ✅ | ✅ | ✅ | ✅ |
| **`protected`** | ✅ | ✅ | ✅ | ❌ |
| **default** (no keyword) | ✅ | ✅ | ❌ | ❌ |
| **`private`** | ✅ | ❌ | ❌ | ❌ |

### Default Access (Package-Private)

When you write no access modifier, the class or member is **package-private** — visible only within the same package:

```java
package com.myapp.model;

class InternalHelper {  // No "public" keyword — package-private
    void doWork() {
        System.out.println("Only classes in com.myapp.model can see me");
    }
}
```

Classes in `com.myapp.service` **cannot** access `InternalHelper` because it is not `public`.

> [!TIP]
> Use default (package-private) access for helper classes that should only be used within their own package. This keeps your public API clean.

## Common Standard Library Packages

Java comes with a massive standard library. Here are the packages you will use most often as a beginner:

| Package | Contains | Example Classes |
| :--- | :--- | :--- |
| **`java.lang`** | Core classes (auto-imported, no `import` needed) | `String`, `Math`, `Integer`, `System`, `Object` |
| **`java.util`** | Collections and utilities | `Scanner`, `ArrayList`, `HashMap`, `Arrays`, `Collections` |
| **`java.io`** | File and stream I/O | `File`, `FileReader`, `BufferedReader`, `FileWriter` |
| **`java.nio`** | New I/O (buffers, channels, paths) | `Path`, `Files`, `Paths` |
| **`java.math`** | Arbitrary-precision arithmetic | `BigInteger`, `BigDecimal` |
| **`java.time`** | Modern date and time API | `LocalDate`, `LocalTime`, `LocalDateTime` |
| **`java.net`** | Networking | `URL`, `HttpURLConnection`, `Socket` |

> [!NOTE]
> `java.lang` is the **only** package that Java imports automatically. For every other package, you must write an explicit `import` statement.

---

## The `java.lang` Package — What is Auto-Imported?

You can use these classes without writing any `import`:

```java
public class AutoImportDemo {
    public static void main(String[] args) {
        // String — from java.lang
        String greeting = "Hello";

        // Math — from java.lang
        double result = Math.pow(2, 10);

        // System — from java.lang
        System.out.println(greeting + " — 2^10 = " + result);

        // Integer — from java.lang
        int parsed = Integer.parseInt("42");
        System.out.println("Parsed: " + parsed);
    }
}
```

No `import` is needed because `String`, `Math`, `System`, and `Integer` all live in `java.lang`.

## One File vs Multiple Classes

### One Public Class Per File

Java enforces that **each `.java` file can have at most one `public` class**, and the file name must match that class name.

```java
// File: Calculator.java
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }
}
```

If the class is called `Calculator`, the file **must** be named `Calculator.java`.

### Multiple Non-Public Classes in One File

You can define multiple non-public classes in a single file, but this is discouraged for readability:

```java
// File: Demo.java
public class Demo {
    public static void main(String[] args) {
        Helper h = new Helper();
        h.greet();
    }
}

class Helper {  // Not public — allowed in the same file
    void greet() {
        System.out.println("Hello from Helper");
    }
}
```

> [!TIP]
> Best practice: **one class per file**. This makes code easier to find, read, and maintain.

## Putting It All Together — A Complete Multi-File Example

Here is a small project with proper packages:

### File: `src/com/school/Main.java`

```java
package com.school;

import com.school.model.Student;
import com.school.service.GradeService;

public class Main {
    public static void main(String[] args) {
        Student student = new Student("Ravi", 85);
        GradeService gradeService = new GradeService();

        String grade = gradeService.calculateGrade(student.getMarks());
        System.out.println(student.getName() + " got grade: " + grade);
    }
}
```

### File: `src/com/school/model/Student.java`

```java
package com.school.model;

public class Student {
    private String name;
    private int marks;

    public Student(String name, int marks) {
        this.name = name;
        this.marks = marks;
    }

    public String getName() {
        return name;
    }

    public int getMarks() {
        return marks;
    }
}
```

### File: `src/com/school/service/GradeService.java`

```java
package com.school.service;

public class GradeService {
    public String calculateGrade(int marks) {
        if (marks >= 90) return "A";
        if (marks >= 80) return "B";
        if (marks >= 70) return "C";
        if (marks >= 60) return "D";
        return "F";
    }
}
```

### Compile and Run

```text
javac -d bin src/com/school/Main.java src/com/school/model/Student.java src/com/school/service/GradeService.java

java -cp bin com.school.Main
```

Output:

```text
Ravi got grade: B
```

This is how real Java projects are structured — classes separated by responsibility, each in its own package, compiled together, and run from a single entry point.

## Summary

| Concept | Key Points |
| :--- | :--- |
| **Package** | A namespace that groups related classes; maps directly to folder structure |
| **`package` statement** | Must be the first line; only one per file; must match the folder path |
| **`import` statement** | Brings classes from other packages into scope; use `*` for all classes in a package |
| **Static import** | Import static members (`import static java.lang.Math.PI`) to use them without the class name |
| **Default package** | No `package` statement; fine for quick tests but not for real projects |
| **Folder structure** | `src/` for source, `bin/` for compiled output, `lib/` for JARs |
| **Classpath** | Tells JVM where to find `.class` files; set with `-cp` flag |
| **Access modifiers** | `public` (everywhere), `protected` (package + subclass), default (package only), `private` (class only) |
| **`java.lang`** | Auto-imported; contains `String`, `Math`, `System`, `Integer`, etc. |
| **One public class per file** | File name must match the public class name |
