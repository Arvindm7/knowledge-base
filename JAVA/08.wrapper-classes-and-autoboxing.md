# Wrapper Classes and Autoboxing

> Every primitive type in Java has a corresponding wrapper class that turns it into an object — enabling primitives to work with collections, generics, and utility methods.

## What You'll Learn

- Useful utility methods in each wrapper class

- `null` handling — a power and a danger of wrappers

- Practical examples and common pitfalls

## Why Do Wrapper Classes Exist?

Java has two categories of types:

| Category | Examples | Stored On |
| :--- | :--- | :--- |
| **Primitives** | `int`, `double`, `boolean`, `char` | Stack (fast, lightweight) |
| **Objects** | `String`, `Scanner`, `ArrayList` | Heap (flexible, feature-rich) |

Primitives are fast and simple, but they **cannot** be used in places that require objects:

```java
// This does NOT compile — ArrayList only works with objects, not primitives
ArrayList<int> numbers = new ArrayList<int>();  // ❌ Compilation error

// This works — Integer is the wrapper class for int
ArrayList<Integer> numbers = new ArrayList<Integer>();  // ✅
```

Wrapper classes solve this by **wrapping** a primitive value inside an object.

---

## The 8 Wrapper Classes

Every primitive type has exactly one corresponding wrapper class in `java.lang`:

| Primitive | Wrapper Class | Example |
| :--- | :--- | :--- |
| `byte` | `Byte` | `Byte b = 10;` |
| `short` | `Short` | `Short s = 100;` |
| `int` | `Integer` | `Integer i = 42;` |
| `long` | `Long` | `Long l = 100L;` |
| `float` | `Float` | `Float f = 3.14f;` |
| `double` | `Double` | `Double d = 3.14;` |
| `char` | `Character` | `Character c = 'A';` |
| `boolean` | `Boolean` | `Boolean flag = true;` |

> [!NOTE]
> All wrapper classes are in `java.lang`, so they are **auto-imported** — no `import` statement needed.

Notice the naming pattern: most wrappers are simply the capitalised full name of the primitive. The two exceptions are `Integer` (not `Int`) and `Character` (not `Char`).

## Creating Wrapper Objects

### Method 1: `valueOf()` — The Recommended Way

```java
Integer num = Integer.valueOf(42);
Double pi = Double.valueOf(3.14);
Boolean flag = Boolean.valueOf(true);
Character letter = Character.valueOf('A');
```

`valueOf()` is preferred because it can **cache and reuse** frequently used values (more on this later), saving memory.

### Method 2: Autoboxing — The Simplest Way

```java
Integer num = 42;        // Java automatically wraps 42 into an Integer object
Double pi = 3.14;        // Java automatically wraps 3.14 into a Double object
Boolean flag = true;     // Java automatically wraps true into a Boolean object
```

This is called **autoboxing** — Java handles the conversion for you. Under the hood, the compiler converts `Integer num = 42` into `Integer num = Integer.valueOf(42)`.

### Method 3: `new` Constructor — Deprecated (Do NOT Use)

```java
// DEPRECATED since Java 9 — do NOT use this
Integer num = new Integer(42);  // ⚠️ Creates a new object every time, wastes memory
```

The `new` constructor was deprecated because it always creates a new object, bypassing the internal cache that `valueOf()` uses.

## Autoboxing and Unboxing

### Autoboxing — Primitive → Wrapper (Automatic)

Java automatically converts a primitive to its wrapper class when needed:

```java
public class AutoboxingDemo {
    public static void main(String[] args) {
        // Autoboxing: int → Integer
        Integer a = 100;

        // Autoboxing in a method call
        printNumber(200);  // int 200 is autoboxed to Integer

        // Autoboxing in a collection
        ArrayList<Integer> list = new ArrayList<>();
        list.add(10);   // int 10 is autoboxed to Integer
        list.add(20);   // int 20 is autoboxed to Integer
    }

    static void printNumber(Integer num) {
        System.out.println("Number: " + num);
    }
}
```

### Unboxing — Wrapper → Primitive (Automatic)

Java automatically converts a wrapper object back to its primitive when needed:

```java
public class UnboxingDemo {
    public static void main(String[] args) {
        Integer wrapped = 42;

        // Unboxing: Integer → int
        int primitive = wrapped;

        // Unboxing in arithmetic
        int result = wrapped + 8;  // Integer is unboxed to int, then 42 + 8 = 50

        // Unboxing in a condition
        Boolean flag = true;
        if (flag) {  // Boolean is unboxed to boolean
            System.out.println("It's true!");
        }
    }
}
```

### What the Compiler Actually Does

When you write:

```java
Integer x = 10;       // You write this
Integer x = Integer.valueOf(10);  // Compiler converts to this (autoboxing)

int y = x;            // You write this
int y = x.intValue(); // Compiler converts to this (unboxing)
```

Autoboxing and unboxing are purely **compile-time sugar** — the compiler inserts the conversion calls for you.

## Parsing — Converting Strings to Numbers

One of the most common uses of wrapper classes is **parsing strings into numbers**:

### `parseXxx()` — Returns a Primitive

```java
int age = Integer.parseInt("25");           // "25" → int 25
double price = Double.parseDouble("19.99"); // "19.99" → double 19.99
long big = Long.parseLong("1000000");       // "1000000" → long 1000000
boolean flag = Boolean.parseBoolean("true"); // "true" → boolean true
float pi = Float.parseFloat("3.14");        // "3.14" → float 3.14
```

### `valueOf()` — Returns a Wrapper Object

```java
Integer age = Integer.valueOf("25");         // "25" → Integer 25
Double price = Double.valueOf("19.99");      // "19.99" → Double 19.99
```

### Difference Between `parseInt()` and `valueOf()`

| Method | Returns | Use When |
| :--- | :--- | :--- |
| `Integer.parseInt("42")` | `int` (primitive) | You need a primitive value |
| `Integer.valueOf("42")` | `Integer` (object) | You need a wrapper object |

### Handling Invalid Input

If the string is not a valid number, a `NumberFormatException` is thrown:

```java
public class ParseSafely {
    public static void main(String[] args) {
        String input = "abc";

        try {
            int num = Integer.parseInt(input);
            System.out.println("Parsed: " + num);
        } catch (NumberFormatException e) {
            System.out.println("'" + input + "' is not a valid number");
        }
    }
}
```

Output:

```text
'abc' is not a valid number
```

> [!TIP]
> Always wrap `parseInt()` / `parseDouble()` in a `try-catch` when the input comes from a user or an external source. You cannot trust external data to be valid.

## Converting Numbers to Strings

There are three common ways to convert a number to a `String`:

```java
int num = 42;

// Method 1: String.valueOf()
String s1 = String.valueOf(num);        // "42"

// Method 2: Integer.toString()
String s2 = Integer.toString(num);      // "42"

// Method 3: Concatenation with empty string
String s3 = num + "";                   // "42"

// Bonus: Convert to different bases
String binary = Integer.toBinaryString(42);  // "101010"
String octal = Integer.toOctalString(42);    // "52"
String hex = Integer.toHexString(42);        // "2a"
```

## Useful Utility Methods

Wrapper classes come with many helpful static methods and constants:

### `Integer` Utilities

```java
// Constants
System.out.println(Integer.MAX_VALUE);  // 2147483647
System.out.println(Integer.MIN_VALUE);  // -2147483648
System.out.println(Integer.SIZE);       // 32 (bits)
System.out.println(Integer.BYTES);      // 4

// Comparison
int result = Integer.compare(10, 20);   // -1 (10 < 20)
int max = Integer.max(10, 20);          // 20
int min = Integer.min(10, 20);          // 10
int sum = Integer.sum(10, 20);          // 30

// Base conversion
int fromBinary = Integer.parseInt("1010", 2);   // 10
int fromHex = Integer.parseInt("FF", 16);       // 255
```

### `Character` Utilities

```java
char ch = 'A';

Character.isLetter(ch)      // true
Character.isDigit(ch)       // false
Character.isLetterOrDigit(ch) // true
Character.isUpperCase(ch)   // true
Character.isLowerCase(ch)   // false
Character.isWhitespace(' ') // true

Character.toUpperCase('a')  // 'A'
Character.toLowerCase('A')  // 'a'
```

### `Double` Utilities

```java
System.out.println(Double.MAX_VALUE);         // 1.7976931348623157E308
System.out.println(Double.MIN_VALUE);         // 4.9E-324
System.out.println(Double.isNaN(0.0 / 0.0));  // true
System.out.println(Double.isInfinite(1.0 / 0.0)); // true
```

## Comparing Wrapper Objects — The `==` Trap

This is one of the **most dangerous pitfalls** in Java. Understanding it will prevent subtle bugs.

### The Problem

```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b);  // true ✅

Integer c = 128;
Integer d = 128;
System.out.println(c == d);  // false ❌ — Wait, what?!
```

Both pairs have the same value, but `==` gives different results. Why?

### The Integer Cache

Java caches `Integer` objects for values **-128 to 127**. When you use autoboxing or `valueOf()` with a value in this range, Java returns the **same cached object**:

```text
Integer a = 127;  → Returns cached object #127
Integer b = 127;  → Returns the SAME cached object #127
a == b  → true (same object in memory)

Integer c = 128;  → Creates a NEW object (128 is outside the cache)
Integer d = 128;  → Creates ANOTHER new object
c == d  → false (different objects in memory)
```

### The Fix — Always Use `.equals()`

```java
Integer c = 128;
Integer d = 128;

System.out.println(c == d);       // false — compares memory addresses
System.out.println(c.equals(d));  // true — compares values ✅
```

> [!IMPORTANT]
> **Rule:** Never use `==` to compare wrapper objects. Always use `.equals()`. The `==` operator compares **object references** (memory addresses), not values. This applies to `Integer`, `Long`, `Double`, `Boolean`, and all wrapper types.

### Which Types Have Caching?

| Wrapper | Cached Range |
| :--- | :--- |
| `Byte` | -128 to 127 (all values) |
| `Short` | -128 to 127 |
| `Integer` | -128 to 127 |
| `Long` | -128 to 127 |
| `Character` | 0 to 127 |
| `Boolean` | `TRUE` and `FALSE` (both cached) |
| `Float` | No cache |
| `Double` | No cache |

## `null` — A Power and a Danger

Unlike primitives, wrapper objects can be `null`. This is both useful and dangerous.

### Useful — Representing "No Value"

```java
public class NullExample {
    // A method that might not find a result
    static Integer findIndex(int[] arr, int target) {
        for (int i = 0; i < arr.length; i++) {
            if (arr[i] == target) return i;  // Autoboxing
        }
        return null;  // "Not found" — primitives can't express this
    }

    public static void main(String[] args) {
        int[] data = {10, 20, 30};
        Integer index = findIndex(data, 20);

        if (index != null) {
            System.out.println("Found at index: " + index);
        } else {
            System.out.println("Not found");
        }
    }
}
```

A primitive `int` cannot be `null` — it must always have a value (`0` by default). A wrapper `Integer` can be `null`, meaning "no value exists."

### Dangerous — `NullPointerException` on Unboxing

```java
Integer num = null;
int value = num;  // 💥 NullPointerException! Java tries to call num.intValue() on null
```

This is called **null unboxing** and is a very common source of bugs:

```java
public class NullUnboxingBug {
    static Integer getAge() {
        return null;  // Maybe from a database that has no value
    }

    public static void main(String[] args) {
        int age = getAge();  // 💥 NullPointerException
    }
}
```

### The Fix — Check for `null` Before Unboxing

```java
Integer age = getAge();

if (age != null) {
    int primitiveAge = age;  // Safe unboxing
    System.out.println("Age: " + primitiveAge);
} else {
    System.out.println("Age is unknown");
}
```

> [!WARNING]
> Whenever a wrapper variable might be `null`, **always check for `null` before unboxing** it to a primitive. Failing to do so is one of the most common causes of `NullPointerException` in Java applications.

## When to Use Primitives vs Wrappers

| Use Primitives When | Use Wrappers When |
| :--- | :--- |
| Performance matters (loops, calculations) | Working with collections (`ArrayList`, `HashMap`) |
| The value is never `null` | The value might be absent (`null`) |
| Simple local variables | Generics require objects (`List<Integer>`) |
| Default value of `0`/`false` is acceptable | You need utility methods (`parseInt`, `compare`) |
| High-frequency operations | API/method signatures that use objects |

### General Rule

> Prefer **primitives** by default. Use **wrappers** only when you have a specific reason — collections, nullability, or utility methods.

## Practical Example — Grade Calculator with Parsing

```java
import java.util.Scanner;
import java.util.ArrayList;

public class GradeCalculator {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        ArrayList<Integer> marks = new ArrayList<>();

        System.out.println("Enter marks (type 'done' to finish):");

        while (sc.hasNext()) {
            String input = sc.next();

            if (input.equalsIgnoreCase("done")) {
                break;
            }

            try {
                int mark = Integer.parseInt(input);  // Parse string → int

                if (mark < 0 || mark > 100) {
                    System.out.println("Mark must be 0-100. Skipping: " + mark);
                    continue;
                }

                marks.add(mark);  // Autoboxing: int → Integer
            } catch (NumberFormatException e) {
                System.out.println("Invalid number: '" + input + "'. Skipping.");
            }
        }

        if (marks.isEmpty()) {
            System.out.println("No marks entered.");
            sc.close();
            return;
        }

        // Calculate statistics using unboxing
        int total = 0;
        int max = Integer.MIN_VALUE;
        int min = Integer.MAX_VALUE;

        for (Integer mark : marks) {  // Unboxing happens in arithmetic below
            total += mark;
            max = Integer.max(max, mark);
            min = Integer.min(min, mark);
        }

        double average = (double) total / marks.size();

        System.out.println("\n--- RESULTS ---");
        System.out.printf("Subjects:  %d%n", marks.size());
        System.out.printf("Total:     %d%n", total);
        System.out.printf("Average:   %.2f%n", average);
        System.out.printf("Highest:   %d%n", max);
        System.out.printf("Lowest:    %d%n", min);

        sc.close();
    }
}
```

This example combines:
- **Parsing** (`Integer.parseInt`) to convert user input
- **Autoboxing** (`marks.add(mark)`) to store primitives in an `ArrayList`
- **Unboxing** (`total += mark`) to do arithmetic with wrapper objects
- **Utility methods** (`Integer.max`, `Integer.min`, `Integer.MIN_VALUE`)
- **Error handling** (`NumberFormatException`) for invalid input

## Summary

| Concept | Key Points |
| :--- | :--- |
| **Wrapper classes** | Object versions of the 8 primitives; all in `java.lang` |
| **Autoboxing** | Automatic `primitive → wrapper` conversion by the compiler |
| **Unboxing** | Automatic `wrapper → primitive` conversion by the compiler |
| **`parseInt()` / `parseDouble()`** | Converts a `String` to a primitive; throws `NumberFormatException` on invalid input |
| **`valueOf()`** | Converts a `String` or primitive to a wrapper object; uses caching |
| **Integer cache** | Values -128 to 127 are cached; `==` works only within this range |
| **Comparing wrappers** | Always use `.equals()`, never `==` |
| **`null` danger** | Wrappers can be `null`; unboxing `null` throws `NullPointerException` |
| **Utility methods** | `MAX_VALUE`, `MIN_VALUE`, `compare()`, `max()`, `min()`, `toBinaryString()` |
| **Primitives vs wrappers** | Default to primitives; use wrappers for collections, nullability, and generics |
