# Methods in Java

> A method is a reusable block of code that performs a specific task — it takes input, processes it, and optionally returns a result.

## What is a Method?

A **method** is a named block of code that you define once and can call (execute) multiple times. Methods let you:

1. **Avoid repetition** — write the logic once, use it everywhere
2. **Organise code** — break a large program into smaller, manageable pieces
3. **Improve readability** — a well-named method tells the reader what the code does

Without methods, your `main` method would grow into hundreds of lines — unreadable and unmaintainable.

## Method Syntax

Every method in Java follows this structure:

```java
accessModifier returnType methodName(parameterList) {
    // method body — the code that runs when the method is called
    return value;  // only if returnType is not void
}
```

### Breaking Down Each Part

| Part | What It Does | Example |
| :--- | :--- | :--- |
| **Access modifier** | Controls who can call this method | `public`, `private`, `protected` |
| **Return type** | The type of value the method sends back | `int`, `String`, `void` |
| **Method name** | The name you use to call the method | `calculateSum`, `greet` |
| **Parameter list** | Input values the method receives | `(int a, int b)` |
| **Method body** | The actual code inside `{ }` | Statements and logic |
| **`return` statement** | Sends a value back to the caller | `return a + b;` |

### Example

```java
public class Calculator {
    // Method definition
    public static int add(int a, int b) {
        int sum = a + b;
        return sum;
    }

    public static void main(String[] args) {
        // Method call
        int result = add(10, 20);
        System.out.println("Sum: " + result);  // Sum: 30
    }
}
```

**How this executes step by step:**

1. `main` starts
2. `add(10, 20)` is called — control jumps to the `add` method
3. Inside `add`: `a = 10`, `b = 20`, `sum = 30`
4. `return sum` sends `30` back to `main`
5. `result` receives `30`
6. The result is printed

## `void` Methods — No Return Value

When a method does not need to return anything, use `void` as the return type:

```java
public class Greeter {
    public static void greet(String name) {
        System.out.println("Hello, " + name + "!");
        // No return statement needed
    }

    public static void main(String[] args) {
        greet("Alice");   // Hello, Alice!
        greet("Bob");     // Hello, Bob!
    }
}
```

`void` means "this method performs an action but does not give back a value." You cannot assign its result to a variable:

```java
// WRONG — void methods don't return anything
String result = greet("Alice");  // Compilation error
```

### Early Return in `void` Methods

You can use `return;` (without a value) to exit a void method early:

```java
public static void printPositive(int num) {
    if (num <= 0) {
        System.out.println("Not a positive number");
        return;  // Exit the method early
    }
    System.out.println("Number: " + num);
}
```

## Parameters vs Arguments

These two terms are often confused:

| Term | Meaning | Where |
| :--- | :--- | :--- |
| **Parameter** | Variable declared in the method definition | `int a, int b` in `add(int a, int b)` |
| **Argument** | Actual value passed when calling the method | `10, 20` in `add(10, 20)` |

```java
//                 Parameters (formal)
public static int multiply(int x, int y) {
    return x * y;
}

public static void main(String[] args) {
    //           Arguments (actual values)
    int result = multiply(5, 3);
}
```

Parameters are **placeholders**. Arguments are the **real values** that fill those placeholders.

## Methods That Return Values

Methods can return any data type — primitives, Strings, arrays, or objects:

### Returning a Primitive

```java
public static double circleArea(double radius) {
    return Math.PI * radius * radius;
}
```

### Returning a String

```java
public static String getGreeting(String name, int hour) {
    if (hour < 12) return "Good morning, " + name;
    if (hour < 17) return "Good afternoon, " + name;
    return "Good evening, " + name;
}
```

### Returning an Array

```java
public static int[] getFirstN(int n) {
    int[] numbers = new int[n];
    for (int i = 0; i < n; i++) {
        numbers[i] = i + 1;
    }
    return numbers;
}

public static void main(String[] args) {
    int[] first5 = getFirstN(5);
    for (int num : first5) {
        System.out.print(num + " ");  // 1 2 3 4 5
    }
}
```

> [!IMPORTANT]
> Every code path in a non-void method **must** reach a `return` statement. If the compiler finds a path that does not return a value, it will throw a compilation error.

## Method Overloading

**Method overloading** means defining **multiple methods with the same name** but **different parameter lists** (different number of parameters, different types, or both).

```java
public class MathHelper {
    // Two int parameters
    public static int add(int a, int b) {
        return a + b;
    }

    // Three int parameters
    public static int add(int a, int b, int c) {
        return a + b + c;
    }

    // Two double parameters
    public static double add(double a, double b) {
        return a + b;
    }

    public static void main(String[] args) {
        System.out.println(add(2, 3));          // Calls add(int, int) → 5
        System.out.println(add(2, 3, 4));       // Calls add(int, int, int) → 9
        System.out.println(add(2.5, 3.5));      // Calls add(double, double) → 6.0
    }
}
```

### Overloading Rules

| Can Differ | Cannot Differ |
| :--- | :--- |
| Number of parameters | Return type alone |
| Type of parameters | Parameter names alone |
| Order of parameter types | Access modifier alone |

```java
// WRONG — changing only the return type is NOT overloading
public static int    calculate(int a) { return a; }
public static double calculate(int a) { return a; }  // Compilation error
```

Java decides which overloaded method to call based on the **arguments** you pass — this is resolved at **compile time**.

## The `static` Keyword

You have seen `static` on every method so far. Here is what it means:

### Static Methods — Belong to the Class

A `static` method belongs to the **class itself**, not to any specific object. You can call it without creating an object:

```java
public class Utility {
    public static int square(int n) {
        return n * n;
    }
}

// Call without creating an object:
int result = Utility.square(5);  // 25
```

### Non-Static Methods — Belong to an Object

A non-static (instance) method belongs to an **object**. You must create an object first:

```java
public class Dog {
    String name;

    public Dog(String name) {
        this.name = name;
    }

    // Non-static — needs an object
    public void bark() {
        System.out.println(name + " says: Woof!");
    }
}

// Must create an object first:
Dog myDog = new Dog("Buddy");
myDog.bark();  // Buddy says: Woof!
```

### When to Use `static`

| Use `static` when | Use non-static when |
| :--- | :--- |
| The method does not depend on object state | The method uses instance variables |
| It is a utility/helper function | It needs different behavior per object |
| Examples: `Math.sqrt()`, `Integer.parseInt()` | Examples: `dog.bark()`, `user.getName()` |

> [!NOTE]
> In the `main` method (`public static void main`), `static` is required because `main` is called by the JVM **before** any objects are created. The JVM needs to start your program without creating an instance of your class.

## Variable Scope

**Scope** defines where a variable is visible and can be used.

### Local Variables — Declared Inside a Method

```java
public static void demo() {
    int x = 10;  // x exists only inside demo()
    System.out.println(x);
}
// x does NOT exist here — it is out of scope
```

Local variables:
- Are created when the method is called
- Are destroyed when the method returns
- Must be initialised before use (no default values)
- Cannot be accessed from other methods

### Block-Level Scope

Variables declared inside any `{ }` block (if, for, while) exist only within that block:

```java
public static void blockScope() {
    if (true) {
        int y = 20;  // y exists only inside this if-block
        System.out.println(y);  // OK
    }
    // System.out.println(y);  // ERROR — y is out of scope
}
```

### Method Parameters

Parameters are local variables that receive their values from arguments:

```java
public static void printAge(int age) {
    // age is a local variable within this method
    System.out.println("Age: " + age);
}
```

### Instance Variables — Declared Inside a Class (Not in a Method)

```java
public class Person {
    String name;  // Instance variable — exists as long as the object exists
    int age;      // Instance variable

    public void introduce() {
        // Can access instance variables here
        System.out.println("I'm " + name + ", age " + age);
    }
}
```

Instance variables:
- Belong to the object (each object has its own copy)
- Have default values (`0` for numbers, `null` for objects, `false` for booleans)
- Are accessible from all non-static methods in the class

## Pass by Value — How Java Passes Data

Java is **always pass by value**. This means methods receive a **copy** of the argument, not the original.

### With Primitives — The Original is Unchanged

```java
public class PassByValueDemo {
    public static void changeValue(int num) {
        num = 100;  // Changes the local copy only
        System.out.println("Inside method: " + num);  // 100
    }

    public static void main(String[] args) {
        int x = 10;
        changeValue(x);
        System.out.println("After method: " + x);  // 10 — unchanged!
    }
}
```

`x` is not affected because `changeValue` received a **copy** of `10`, not `x` itself.

### With Objects — The Reference is Copied

When you pass an object, Java copies the **reference** (memory address), not the object itself. Both the original and the copy point to the **same object**:

```java
public class PassObjectDemo {
    public static void changeName(int[] arr) {
        arr[0] = 999;  // Modifies the actual array through the copied reference
    }

    public static void main(String[] args) {
        int[] numbers = {1, 2, 3};
        changeName(numbers);
        System.out.println(numbers[0]);  // 999 — the array WAS modified
    }
}
```

The method received a copy of the **reference**, but both references point to the same array in memory. So modifying the array's contents through either reference affects the same object.

## Recursion — Methods That Call Themselves

A **recursive method** is a method that calls itself to solve a problem by breaking it into smaller sub-problems.

### Example: Factorial

```text
5! = 5 × 4 × 3 × 2 × 1 = 120
```

```java
public class Recursion {
    public static int factorial(int n) {
        // Base case — stops the recursion
        if (n <= 1) {
            return 1;
        }
        // Recursive case — calls itself with a smaller input
        return n * factorial(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(factorial(5));  // 120
    }
}
```

### How It Executes (Call Stack)

```text
factorial(5)
  → 5 * factorial(4)
    → 4 * factorial(3)
      → 3 * factorial(2)
        → 2 * factorial(1)
          → returns 1        ← base case reached
        → returns 2 * 1 = 2
      → returns 3 * 2 = 6
    → returns 4 * 6 = 24
  → returns 5 * 24 = 120
```

### Every Recursive Method Needs Two Things

| Component | Purpose | Without It |
| :--- | :--- | :--- |
| **Base case** | Stops the recursion | Infinite loop → `StackOverflowError` |
| **Recursive case** | Calls itself with a simpler input | Never reaches the base case |

### Example: Fibonacci

```java
public static int fibonacci(int n) {
    if (n <= 0) return 0;  // Base case
    if (n == 1) return 1;  // Base case
    return fibonacci(n - 1) + fibonacci(n - 2);  // Recursive case
}

// fibonacci(6) → 8
// Sequence: 0, 1, 1, 2, 3, 5, 8
```

> [!WARNING]
> Recursion is elegant but can be **slow** for large inputs. The Fibonacci example above has exponential time complexity. For performance-critical code, use loops (iteration) or memoisation instead.

## Best Practices for Writing Methods

### 1. Use Descriptive Names

```java
// BAD
public static int calc(int a, int b) { ... }

// GOOD
public static int calculateArea(int length, int width) { ... }
```

### 2. Keep Methods Small — One Task Per Method

Each method should do **one thing** and do it well. If a method is longer than ~20 lines, consider splitting it.

### 3. Limit the Number of Parameters

Methods with more than 3-4 parameters become hard to read. If you need more, consider grouping them into an object.

### 4. Return Early to Avoid Deep Nesting

```java
// BAD — deeply nested
public static String getGrade(int marks) {
    if (marks >= 0) {
        if (marks >= 90) {
            return "A";
        } else {
            if (marks >= 80) {
                return "B";
            }
        }
    }
    return "F";
}

// GOOD — early returns, flat structure
public static String getGrade(int marks) {
    if (marks >= 90) return "A";
    if (marks >= 80) return "B";
    if (marks >= 70) return "C";
    if (marks >= 60) return "D";
    return "F";
}
```

### 5. Follow Java Naming Convention

| What | Convention | Example |
| :--- | :--- | :--- |
| **Method name** | camelCase, starts with a verb | `calculateTotal`, `isValid`, `getName` |
| **Parameter name** | camelCase | `studentName`, `maxRetries` |
| **Boolean methods** | Start with `is`, `has`, `can` | `isEmpty()`, `hasPermission()` |

## Complete Example — Putting It All Together

```java
import java.util.Scanner;

public class MethodsDemo {
    // Static method — calculates area of a rectangle
    public static double calculateArea(double length, double width) {
        return length * width;
    }

    // Overloaded — calculates area of a square
    public static double calculateArea(double side) {
        return side * side;
    }

    // Overloaded — calculates area of a circle
    public static double calculateCircleArea(double radius) {
        return Math.PI * radius * radius;
    }

    // Void method — prints a separator line
    public static void printSeparator() {
        System.out.println("================================");
    }

    // Method with validation
    public static boolean isValidDimension(double value) {
        return value > 0;
    }

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        printSeparator();
        System.out.println("   AREA CALCULATOR");
        printSeparator();

        System.out.print("Enter rectangle length: ");
        double length = sc.nextDouble();
        System.out.print("Enter rectangle width: ");
        double width = sc.nextDouble();

        if (isValidDimension(length) && isValidDimension(width)) {
            double area = calculateArea(length, width);
            System.out.printf("Rectangle area: %.2f%n", area);
        } else {
            System.out.println("Invalid dimensions!");
        }

        printSeparator();

        System.out.print("Enter square side: ");
        double side = sc.nextDouble();

        if (isValidDimension(side)) {
            System.out.printf("Square area: %.2f%n", calculateArea(side));
        }

        printSeparator();

        System.out.print("Enter circle radius: ");
        double radius = sc.nextDouble();

        if (isValidDimension(radius)) {
            System.out.printf("Circle area: %.2f%n", calculateCircleArea(radius));
        }

        printSeparator();
        sc.close();
    }
}
```

## Summary

| Concept | Key Points |
| :--- | :--- |
| **Method** | A reusable block of code with a name, parameters, and return type |
| **`void`** | Return type for methods that perform an action but return nothing |
| **Parameters** | Variables declared in the method signature; receive values from arguments |
| **Return type** | Must match the value returned; every non-void path must return |
| **Overloading** | Multiple methods with the same name but different parameter lists |
| **`static`** | Method belongs to the class; callable without an object |
| **Scope** | Variables exist only within the block `{ }` where they are declared |
| **Pass by value** | Java copies the value (or reference) — never passes the original variable |
| **Recursion** | A method calling itself; needs a base case and a recursive case |
| **Naming** | camelCase, start with a verb, boolean methods start with `is`/`has`/`can` |
