# Enums

> An enum is a special class that defines a fixed set of named constants — such as days of the week, order statuses, or directions — making code safer and more readable than using plain `int` or `String` values.

## What You'll Learn

- Why enums are better than integer/String constants
- Declaring and using a basic enum
- Built-in methods — `values()`, `valueOf()`, `name()`, `ordinal()`, `compareTo()`
- Enums with fields, constructors, and methods
- Enums with abstract methods (constant-specific behaviour)
- Enums in `switch` statements
- Enums implementing interfaces
- `EnumMap` and `EnumSet`
- Enum as a Singleton
- Common mistakes and a practical example

---

## Why Enums?

Without enums, constants are often plain numbers or strings:

```java
public static final int PENDING = 0;
public static final int SHIPPED = 1;
public static final int DELIVERED = 2;

void update(int status) { ... }
update(99);        // ❌ compiles, but 99 is meaningless
update("hello");   // ❌ (if String) — typo-prone
```

With an enum:

```java
enum OrderStatus { PENDING, SHIPPED, DELIVERED }

void update(OrderStatus status) { ... }
update(OrderStatus.SHIPPED);   // ✅
update(99);                    // ❌ compile error
```

| Plain constants | Enums |
| :--- | :--- |
| Any `int`/`String` accepted | Only the defined values accepted |
| No type safety | Compile-time type safety |
| Printing gives `1` | Printing gives `SHIPPED` |
| Can't hold behaviour | Can have fields and methods |
| No easy iteration | `values()` lists all constants |

## Declaring a Basic Enum

```java
enum Day {
    MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY
}

public class Main {
    public static void main(String[] args) {
        Day today = Day.FRIDAY;

        System.out.println(today);                 // FRIDAY
        System.out.println(today == Day.FRIDAY);   // true
    }
}
```

### Rules

- Constants are written in **UPPER_SNAKE_CASE** by convention.
- Each constant is a **singleton object** of the enum type — compare with `==` (safe and recommended).
- An enum can be a top-level type (own file), or nested inside a class.
- You **cannot** create enum instances with `new`.
- Enums implicitly extend `java.lang.Enum`, so they cannot extend another class (but can implement interfaces).

## Built-in Enum Methods

```java
enum Level { LOW, MEDIUM, HIGH }

public class Main {
    public static void main(String[] args) {
        // values() — array of all constants
        for (Level l : Level.values()) {
            System.out.println(l + " ordinal=" + l.ordinal());
        }

        // valueOf() — String -> enum
        Level l = Level.valueOf("HIGH");
        System.out.println(l.name());                    // HIGH

        // compareTo() — compares by ordinal
        System.out.println(Level.LOW.compareTo(Level.HIGH));   // negative

        // Level.valueOf("EXTREME");  // 💥 IllegalArgumentException
    }
}
```

**Output:**

```text
LOW ordinal=0
MEDIUM ordinal=1
HIGH ordinal=2
HIGH
-2
```

| Method | Description |
| :--- | :--- |
| `values()` | Returns an array of all constants in declaration order |
| `valueOf(String)` | Converts exact-match name to constant; throws `IllegalArgumentException` if not found |
| `name()` | The constant's name as a `String` |
| `toString()` | Same as `name()` by default (can be overridden) |
| `ordinal()` | Zero-based position in the declaration |
| `compareTo(other)` | Compares by ordinal |
| `equals` / `==` | Identity comparison |

> [!WARNING]
> Avoid relying on `ordinal()` for storage or logic — reordering constants silently changes values. Store `name()` or an explicit field instead.

## Enums with Fields, Constructors, and Methods

Enums are full classes: they can hold data and behaviour.

```java
enum Planet {
    MERCURY(3.303e+23, 2.4397e6),
    EARTH(5.976e+24, 6.37814e6),
    JUPITER(1.9e+27, 7.1492e7);

    private final double mass;      // kg
    private final double radius;    // metres

    Planet(double mass, double radius) {   // constructor is implicitly private
        this.mass = mass;
        this.radius = radius;
    }

    public double getMass()   { return mass; }
    public double getRadius() { return radius; }

    public double surfaceGravity() {
        final double G = 6.67300E-11;
        return G * mass / (radius * radius);
    }
}

public class Main {
    public static void main(String[] args) {
        for (Planet p : Planet.values()) {
            System.out.printf("%-8s gravity = %.2f m/s²%n", p, p.surfaceGravity());
        }
    }
}
```

### Code Explanation

| Part | What it does |
| :--- | :--- |
| `EARTH(5.976e+24, 6.37814e6)` | Calls the constructor to create the `EARTH` object |
| `;` after last constant | **Required** when the enum has fields/methods |
| Constructor | Implicitly `private` — only usable inside the enum |
| `private final` fields | Immutable data attached to each constant |

### A Very Common Pattern: Enum with a Display Name / Code

```java
enum HttpStatus {
    OK(200, "OK"),
    NOT_FOUND(404, "Not Found"),
    SERVER_ERROR(500, "Internal Server Error");

    private final int code;
    private final String message;

    HttpStatus(int code, String message) {
        this.code = code;
        this.message = message;
    }

    public int getCode()       { return code; }
    public String getMessage() { return message; }

    // Reverse lookup: int -> enum
    public static HttpStatus fromCode(int code) {
        for (HttpStatus s : values()) {
            if (s.code == code) return s;
        }
        throw new IllegalArgumentException("Unknown code: " + code);
    }
}

System.out.println(HttpStatus.fromCode(404).getMessage());   // Not Found
```

## Enums in switch

```java
enum Direction { NORTH, SOUTH, EAST, WEST }

public static String describe(Direction d) {
    switch (d) {
        case NORTH: return "Going up";
        case SOUTH: return "Going down";
        case EAST:  return "Going right";
        case WEST:  return "Going left";
        default:    return "Unknown";
    }
}

// Modern switch expression (Java 14+)
public static String describeModern(Direction d) {
    return switch (d) {
        case NORTH -> "Going up";
        case SOUTH -> "Going down";
        case EAST  -> "Going right";
        case WEST  -> "Going left";
    };   // no default needed — all constants covered
}
```

> [!NOTE]
> Inside `case`, write the constant **without** the enum name (`NORTH`, not `Direction.NORTH`).

> [!TIP]
> A switch *expression* over an enum must be exhaustive. If you later add a constant, the compiler flags every switch that forgets it — a big safety benefit.

## Constant-Specific Behaviour (Abstract Methods)

Each constant can provide its own implementation of a method:

```java
enum Operation {
    ADD("+") {
        @Override public double apply(double a, double b) { return a + b; }
    },
    SUBTRACT("-") {
        @Override public double apply(double a, double b) { return a - b; }
    },
    MULTIPLY("*") {
        @Override public double apply(double a, double b) { return a * b; }
    },
    DIVIDE("/") {
        @Override public double apply(double a, double b) {
            if (b == 0) throw new ArithmeticException("Divide by zero");
            return a / b;
        }
    };

    private final String symbol;

    Operation(String symbol) { this.symbol = symbol; }

    public String getSymbol() { return symbol; }

    public abstract double apply(double a, double b);
}

public class Main {
    public static void main(String[] args) {
        for (Operation op : Operation.values()) {
            System.out.println("10 " + op.getSymbol() + " 5 = " + op.apply(10, 5));
        }
    }
}
```

**Output:**

```text
10 + 5 = 15.0
10 - 5 = 5.0
10 * 5 = 50.0
10 / 5 = 2.0
```

This replaces long `if-else`/`switch` chains with polymorphism — new operations are added by adding a constant.

## Enums Implementing Interfaces

Enums cannot extend a class but can implement interfaces:

```java
interface Discount {
    double apply(double price);
}

enum CustomerType implements Discount {
    REGULAR {
        public double apply(double price) { return price; }
    },
    SILVER {
        public double apply(double price) { return price * 0.95; }
    },
    GOLD {
        public double apply(double price) { return price * 0.90; }
    };
}

System.out.println(CustomerType.GOLD.apply(1000));   // 900.0
```

## EnumMap and EnumSet

Specialised, fast collections designed for enum keys/values.

### EnumMap

```java
import java.util.*;

enum Day { MON, TUE, WED, THU, FRI }

EnumMap<Day, String> schedule = new EnumMap<>(Day.class);
schedule.put(Day.WED, "Gym");
schedule.put(Day.MON, "Meeting");

System.out.println(schedule);   // {MON=Meeting, WED=Gym}  — ordered by enum order
```

### EnumSet

```java
EnumSet<Day> weekdays = EnumSet.allOf(Day.class);
EnumSet<Day> none     = EnumSet.noneOf(Day.class);
EnumSet<Day> midWeek  = EnumSet.of(Day.TUE, Day.WED, Day.THU);
EnumSet<Day> range    = EnumSet.range(Day.MON, Day.WED);
EnumSet<Day> others   = EnumSet.complementOf(range);   // THU, FRI
```

| Collection | Compared to `HashMap` / `HashSet` |
| :--- | :--- |
| `EnumMap` | Faster, compact (array-backed), keeps natural enum order |
| `EnumSet` | Extremely fast (bit-vector), keeps natural enum order |

## Enum as a Singleton

Because there is exactly one instance of each constant, a single-constant enum is the simplest **thread-safe, serialization-safe** singleton:

```java
enum DatabaseConnection {
    INSTANCE;

    private int queryCount = 0;

    public void query(String sql) {
        queryCount++;
        System.out.println("Running: " + sql + " (total " + queryCount + ")");
    }
}

DatabaseConnection.INSTANCE.query("SELECT * FROM users");
DatabaseConnection.INSTANCE.query("SELECT * FROM orders");
```

## Nested Enums and State Machines

Enums can model states and legal transitions:

```java
enum TrafficLight {
    RED    { public TrafficLight next() { return GREEN; } },
    GREEN  { public TrafficLight next() { return YELLOW; } },
    YELLOW { public TrafficLight next() { return RED; } };

    public abstract TrafficLight next();
}

TrafficLight light = TrafficLight.RED;
for (int i = 0; i < 4; i++) {
    System.out.print(light + " -> ");
    light = light.next();
}
// RED -> GREEN -> YELLOW -> RED ->
```

## Common Mistakes

| Mistake | Problem | Fix |
| :--- | :--- | :--- |
| `new Day()` | Compile error — enums can't be instantiated | Use constants: `Day.MONDAY` |
| `Day.valueOf("monday")` | `IllegalArgumentException` (case-sensitive) | Use `valueOf(s.toUpperCase())` inside try-catch |
| Storing `ordinal()` in a database | Breaks if constants are reordered | Store `name()` or a code field |
| Forgetting `;` after constants when adding fields | Compile error | Always end the constants list with `;` |
| `case Day.MONDAY:` in a switch | Compile error (older Java) | Use `case MONDAY:` |
| Comparing with `.equals` against `null` constant | NPE if left side is null | `==` is null-safe |
| Extending an enum | Not allowed | Use an interface instead |
| Mutable enum fields | Shared global state bugs | Make fields `final` |

## Practical Example: Order Workflow

```java
import java.util.*;

enum OrderStatus {
    PLACED("Order placed"),
    PACKED("Order packed"),
    SHIPPED("Out for delivery"),
    DELIVERED("Delivered"),
    CANCELLED("Cancelled");

    private final String description;

    OrderStatus(String description) { this.description = description; }

    public String getDescription() { return description; }

    public boolean canMoveTo(OrderStatus next) {
        return switch (this) {
            case PLACED    -> next == PACKED || next == CANCELLED;
            case PACKED    -> next == SHIPPED || next == CANCELLED;
            case SHIPPED   -> next == DELIVERED;
            case DELIVERED, CANCELLED -> false;
        };
    }
}

class Order {
    private final int id;
    private OrderStatus status = OrderStatus.PLACED;

    Order(int id) { this.id = id; }

    public void moveTo(OrderStatus next) {
        if (!status.canMoveTo(next)) {
            System.out.println("❌ Order " + id + ": cannot go from " + status + " to " + next);
            return;
        }
        status = next;
        System.out.println("✅ Order " + id + ": " + status.getDescription());
    }
}

public class Main {
    public static void main(String[] args) {
        Order order = new Order(101);
        order.moveTo(OrderStatus.PACKED);
        order.moveTo(OrderStatus.DELIVERED);   // invalid jump
        order.moveTo(OrderStatus.SHIPPED);
        order.moveTo(OrderStatus.DELIVERED);
        order.moveTo(OrderStatus.CANCELLED);   // invalid after delivery
    }
}
```

**Output:**

```text
✅ Order 101: Order packed
❌ Order 101: cannot go from PACKED to DELIVERED
✅ Order 101: Out for delivery
✅ Order 101: Delivered
❌ Order 101: cannot go from DELIVERED to CANCELLED
```

## Summary

| Concept | Key Point |
| :--- | :--- |
| **Enum** | A fixed set of named constants, each a singleton object |
| **Declaration** | `enum Day { MONDAY, TUESDAY, ... }` |
| **Comparison** | Use `==` |
| **`values()` / `valueOf()`** | Get all constants / convert from String |
| **`name()` / `ordinal()`** | Name and position (avoid persisting `ordinal`) |
| **Fields & constructors** | Attach data to constants; constructor is implicitly private |
| **Abstract methods** | Each constant can override behaviour |
| **Interfaces** | Enums can implement them but cannot extend classes |
| **`switch`** | Use constant names without the enum prefix; switch expressions are exhaustive |
| **`EnumMap` / `EnumSet`** | Fast collections specialised for enums |
| **Singleton** | Single-constant enum is a simple, safe singleton |
