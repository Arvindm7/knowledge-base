# Generics

> Generics let you write classes, interfaces, and methods that work with any type while keeping compile-time type safety — no more casting and no more surprise `ClassCastException`s.

## What You'll Learn

- Why generics exist (the problem with raw types and `Object`)
- Generic classes with type parameters
- Generic methods
- Multiple type parameters
- Bounded type parameters (`extends`)
- Generic interfaces
- Wildcards — `?`, `? extends`, `? super` (PECS rule)
- Type erasure and its limitations
- The diamond operator `<>`
- Common mistakes and a practical example

---

## Why Generics?

Before generics, collections stored plain `Object`s:

```java
import java.util.*;

List list = new ArrayList();       // raw type
list.add("Hello");
list.add(42);                      // compiler allows anything

String s = (String) list.get(1);   // 💥 ClassCastException at runtime
```

Problems: you must **cast** everywhere, and errors appear only at **runtime**.

With generics:

```java
List<String> list = new ArrayList<>();
list.add("Hello");
// list.add(42);                   // ❌ Compile error — caught early!

String s = list.get(0);            // ✅ no cast needed
```

| Without generics | With generics |
| :--- | :--- |
| Casting required | No casting |
| Errors at **runtime** | Errors at **compile time** |
| Unclear what a collection holds | Type is documented in code: `List<String>` |

## Generic Classes

A **type parameter** (written in `<>`) acts as a placeholder for a real type.

```java
class Box<T> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }

    public void setValue(T value) {
        this.value = value;
    }
}

public class Main {
    public static void main(String[] args) {
        Box<String> nameBox = new Box<>("Alice");
        Box<Integer> ageBox = new Box<>(25);

        String name = nameBox.getValue();   // no cast
        int age = ageBox.getValue();

        System.out.println(name + " is " + age);
        // nameBox.setValue(10);            // ❌ compile error
    }
}
```

### Code Explanation

| Part | What it does |
| :--- | :--- |
| `class Box<T>` | Declares a type parameter `T` |
| `private T value` | Field whose type is decided by the user of the class |
| `new Box<>("Alice")` | `T` becomes `String` (inferred by the diamond `<>`) |
| `Box<Integer>` | `T` becomes `Integer` (wrapper class — primitives are not allowed) |

> [!IMPORTANT]
> Type arguments must be **objects**: `Box<int>` is illegal; use `Box<Integer>`.

### Naming Conventions

| Letter | Meaning |
| :--- | :--- |
| `T` | Type |
| `E` | Element (collections) |
| `K` | Key |
| `V` | Value |
| `N` | Number |
| `R` | Return type |

## Multiple Type Parameters

```java
class Pair<K, V> {
    private final K key;
    private final V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey()   { return key; }
    public V getValue() { return value; }

    @Override
    public String toString() {
        return "(" + key + ", " + value + ")";
    }
}

Pair<String, Integer> p1 = new Pair<>("Alice", 90);
Pair<Integer, String> p2 = new Pair<>(1, "First");
System.out.println(p1);   // (Alice, 90)
System.out.println(p2);   // (1, First)
```

This is exactly how `Map<K, V>` is defined.

## Generic Methods

A method can declare its **own** type parameter, placed **before the return type**.

```java
public class Utils {

    public static <T> void printArray(T[] array) {
        for (T item : array) {
            System.out.print(item + " ");
        }
        System.out.println();
    }

    public static <T> T firstElement(List<T> list) {
        return list.get(0);
    }

    public static <T> void swap(T[] arr, int i, int j) {
        T temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }
}

Integer[] nums = {1, 2, 3};
String[] words = {"a", "b", "c"};

Utils.printArray(nums);      // 1 2 3
Utils.printArray(words);     // a b c
Utils.swap(words, 0, 2);     // [c, b, a]
```

| Part | Meaning |
| :--- | :--- |
| `<T>` before `void` | Declares the method's type parameter |
| `T[] array` | Works for any object array |
| Type inference | Java figures out `T` from the arguments — no need to write `Utils.<Integer>printArray(...)` |

## Bounded Type Parameters

Restrict which types are allowed using `extends` (for classes **and** interfaces).

```java
class Calculator<T extends Number> {
    private T value;

    public Calculator(T value) { this.value = value; }

    public double doubled() {
        return value.doubleValue() * 2;   // Number methods available
    }
}

Calculator<Integer> c1 = new Calculator<>(10);
Calculator<Double>  c2 = new Calculator<>(2.5);
// Calculator<String> c3 = ...            // ❌ String is not a Number
```

### Bounded Method with `Comparable`

```java
public static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}

System.out.println(max(10, 20));            // 20
System.out.println(max("apple", "pear"));   // pear
```

Because `T extends Comparable<T>`, the compiler knows `compareTo` exists.

### Multiple Bounds

```java
class Demo<T extends Number & Comparable<T>> { }   // class first, then interfaces
```

## Generic Interfaces

```java
interface Repository<T, ID> {
    void save(T item);
    T findById(ID id);
    List<T> findAll();
}

class Student {
    int id; String name;
    Student(int id, String name) { this.id = id; this.name = name; }
}

class StudentRepository implements Repository<Student, Integer> {
    private final Map<Integer, Student> store = new HashMap<>();

    @Override
    public void save(Student s) { store.put(s.id, s); }

    @Override
    public Student findById(Integer id) { return store.get(id); }

    @Override
    public List<Student> findAll() { return new ArrayList<>(store.values()); }
}
```

The implementing class either **fixes** the types (`Repository<Student, Integer>`) or stays generic itself (`class MyRepo<T, ID> implements Repository<T, ID>`).

## Wildcards

### The Problem: `List<Integer>` is NOT a `List<Number>`

```java
List<Integer> ints = new ArrayList<>();
// List<Number> nums = ints;    // ❌ Compile error!
```

Even though `Integer` extends `Number`, generics are **invariant**. If this were allowed, you could add a `Double` into a list of integers.

### The Wildcard `?`

| Syntax | Name | Meaning |
| :--- | :--- | :--- |
| `List<?>` | Unbounded | A list of **unknown** type |
| `List<? extends Number>` | Upper bounded | List of `Number` **or any subclass** |
| `List<? super Integer>` | Lower bounded | List of `Integer` **or any superclass** |

### Upper Bounded — Reading (Producer)

```java
public static double sum(List<? extends Number> list) {
    double total = 0;
    for (Number n : list) {
        total += n.doubleValue();
    }
    return total;
}

sum(List.of(1, 2, 3));          // List<Integer> ✅
sum(List.of(1.5, 2.5));         // List<Double>  ✅
```

You can **read** items as `Number`, but you **cannot add** (except `null`) — the compiler doesn't know the exact type.

### Lower Bounded — Writing (Consumer)

```java
public static void addNumbers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
}

List<Number> numbers = new ArrayList<>();
List<Object> objects = new ArrayList<>();
addNumbers(numbers);   // ✅
addNumbers(objects);   // ✅
```

### PECS Rule

> **P**roducer **E**xtends, **C**onsumer **S**uper

| If the collection... | Use |
| :--- | :--- |
| **Produces** data you read from | `? extends T` |
| **Consumes** data you write into | `? super T` |
| Both | Use exact type `T` |

```java
// Copy from src (producer) to dest (consumer)
public static <T> void copy(List<? extends T> src, List<? super T> dest) {
    for (T item : src) {
        dest.add(item);
    }
}
```

### Unbounded `?`

```java
public static void printAll(List<?> list) {
    for (Object o : list) {
        System.out.println(o);
    }
}
```

## Type Erasure and Limitations

Generics exist only at **compile time**. The compiler removes (erases) type information and inserts casts, so at runtime `List<String>` and `List<Integer>` are both just `List`.

### What You Cannot Do

| Restriction | Example | Why |
| :--- | :--- | :--- |
| Use primitives | `Box<int>` | Type arguments must be objects |
| Create instance of `T` | `new T()` | Type unknown at runtime |
| Create generic array | `new T[10]` / `new List<String>[10]` | Arrays need runtime type info |
| `instanceof` with type argument | `obj instanceof List<String>` | Erased at runtime |
| Static field of type `T` | `static T value;` | Static is shared by all `T`s |
| Overload by type argument | `void f(List<String>)` and `void f(List<Integer>)` | Same erasure → clash |
| Catch / throw generic type | `class MyEx<T> extends Exception` | Not allowed |

```java
// Workaround for creating a generic array
@SuppressWarnings("unchecked")
T[] arr = (T[]) new Object[10];
```

## Diamond Operator `<>`

Since Java 7, the right side's type arguments can be inferred:

```java
Map<String, List<Integer>> map = new HashMap<String, List<Integer>>();  // old
Map<String, List<Integer>> map = new HashMap<>();                       // modern
```

`var` (Java 10+) goes further for local variables:

```java
var list = new ArrayList<String>();   // type inferred as ArrayList<String>
```

## Common Mistakes

| Mistake | Problem | Fix |
| :--- | :--- | :--- |
| Using raw types (`List list`) | Loses type safety, warnings | Always specify `List<String>` |
| `Box<int>` | Compile error | Use wrapper `Box<Integer>` |
| Assuming `List<Integer>` is a `List<Number>` | Compile error | Use `List<? extends Number>` |
| Adding to `List<? extends T>` | Compile error | Use `? super T` for writing |
| `new T()` | Not allowed | Pass a `Supplier<T>` or `Class<T>` |
| Calling `t.compareTo(x)` on unbounded `T` | Method not found | Add `T extends Comparable<T>` |
| Ignoring unchecked warnings | Hidden `ClassCastException` | Fix the cause; `@SuppressWarnings` only when sure |

## Practical Example: Generic Stack

```java
import java.util.*;

class GenericStack<T> {
    private final List<T> items = new ArrayList<>();

    public void push(T item) {
        items.add(item);
    }

    public T pop() {
        if (isEmpty()) {
            throw new RuntimeException("Stack is empty");
        }
        return items.remove(items.size() - 1);
    }

    public T peek() {
        if (isEmpty()) {
            throw new RuntimeException("Stack is empty");
        }
        return items.get(items.size() - 1);
    }

    public boolean isEmpty() { return items.isEmpty(); }
    public int size()        { return items.size(); }
}

public class Main {
    public static void main(String[] args) {
        GenericStack<String> books = new GenericStack<>();
        books.push("Java");
        books.push("Python");
        books.push("C++");

        System.out.println(books.pop());    // C++
        System.out.println(books.peek());   // Python

        GenericStack<Integer> numbers = new GenericStack<>();
        numbers.push(10);
        numbers.push(20);
        System.out.println(numbers.pop() + numbers.pop());  // 30
    }
}
```

One class, any type, fully type-safe.

## Summary

| Concept | Key Point |
| :--- | :--- |
| **Generics** | Type parameters give compile-time type safety and remove casts |
| **Generic class** | `class Box<T>` — `T` replaced by a real type on use |
| **Multiple types** | `class Pair<K, V>` |
| **Generic method** | `public static <T> void f(T x)` — type parameter before return type |
| **Bounded type** | `<T extends Number>` restricts allowed types |
| **Generic interface** | `interface Repository<T, ID>` |
| **Wildcards** | `?`, `? extends T` (read), `? super T` (write) |
| **PECS** | Producer Extends, Consumer Super |
| **Type erasure** | Generic info removed at runtime → some restrictions |
| **Diamond `<>`** | Compiler infers type arguments |
