# Object Cloning in Java

**Object cloning** refers to the process of creating an exact copy (or near-identical copy) of an existing object. The cloned object has the same structure and data as the original object but occupies a **different memory location** on the heap.

In Java, object cloning is supported via the `java.lang.Cloneable` interface and the `clone()` method defined in the `java.lang.Object` class.

## What is Object Cloning?

When an object is cloned:
- A new instance of the class is allocated in memory.
- The state (fields and values) of the original object is copied over to the new instance.
- Modifications made to the cloned object do not affect the original object (with caveats regarding reference types in shallow cloning).

```
Original Object (Heap Address: 0x100) ──[ clone() ]──> Cloned Object (Heap Address: 0x200)
```

### Key Characteristics

- **Memory Independence:** The cloned object resides at a separate heap memory address (`original != cloned` is `true`).
- **Class Equality:** Both objects belong to the exact same class (`original.getClass() == cloned.getClass()` is `true`).
- **Content Equivalence:** Initially, both objects have identical field values (`original.equals(cloned)` is typically `true` if `equals()` is properly implemented).

---

## Purpose Behind Using Object Cloning

Object cloning is commonly used in software engineering for several reasons:

1. **Efficiency & Performance:** Instead of creating a new object from scratch using the `new` keyword and re-running expensive initialization logic (e.g., database queries or complex calculations), cloning copies existing field values directly.
2. **State Preservation (Snapshots / Mementos):** Cloning allows capturing an object's current state for operations such as **Undo/Redo**, transactional rollbacks, or caching.
3. **Reducing Coupling:** It ensures methods can work with a copy of an object without risking unintended modifications to the caller's original instance.
4. **Working with Immutable Objects:** When you need a slightly modified version of an otherwise immutable structure, cloning creates an editable duplicate.
5. **Design Patterns (Prototype Pattern):** The **Prototype Design Pattern** relies directly on object cloning to generate new objects by copying pre-configured prototypes.

## How Cloning Works in Java

Cloning in Java is governed by two core components and an exception:

### 1. The `Cloneable` Interface
- Located in `java.lang.Cloneable`.
- It is a **marker interface** (it contains **no methods**).
- Its sole purpose is to signal to the JVM that the `Object.clone()` method is safe and legally allowed to be called on instances of this class.
- If `clone()` is called on an object whose class does not implement `Cloneable`, the JVM throws a `CloneNotSupportedException`.

### 2. The `Object.clone()` Method
- Defined in `java.lang.Object` with signature: `protected Object clone() throws CloneNotSupportedException`.
- By default, `Object.clone()` performs a **bitwise / field-by-field shallow copy**:
  - Primitive fields (`int`, `double`, `boolean`, etc.) are copied by value.
  - Reference fields (objects, arrays) are copied by reference (both original and clone point to the same nested object).
- Because it is `protected` in `Object`, any class that needs to be cloned must **override** `clone()` and declare it as `public` (or `protected`) to be accessible.

### 3. The `CloneNotSupportedException`
- A checked exception thrown at runtime if a class invokes `super.clone()` without implementing the `Cloneable` interface.

## Types of Cloning

Java supports two types of object cloning:

| Type | Copies Primitives | Copies Nested Objects | Shared References? |
| :--- | :---: | :---: | :---: |
| **Shallow Cloning** | By Value | By Reference | ✅ Yes (Nested objects are shared) |
| **Deep Cloning** | By Value | By Value (New Objects) | ❌ No (Everything is fully independent) |

---

## 1. Shallow Cloning

### Definition

**Shallow cloning** creates a new object and copies all primitive field values directly. However, for any **reference-type fields** (such as nested objects, lists, or arrays), only the **memory references** are copied — not the actual objects they point to.

This means both the original object and the cloned object **share the exact same nested instances**. Modifying a mutable nested object through the clone will unintentionally modify it in the original object as well.

### Shallow Cloning Example

```java
import java.util.*;

// Address class (Nested Reference Type - NOT Cloneable)
class Address {
    String city;

    // Constructor
    Address(String city) {
        this.city = city;
    }
}

// Person class implementing Cloneable
class Person implements Cloneable {
    String name;      // Primitive / String field
    Address address;  // Reference-type field

    // Constructor
    Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    // Overriding clone() from Object class
    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone(); // Performs default shallow copy
    }
}

class Main {
    public static void main(String[] args) throws CloneNotSupportedException {
        Address address = new Address("Mumbai");
        Person person = new Person("Rahul", address);

        // Cloning person (Shallow Copy)
        Person clonedPerson = (Person) person.clone();

        // Modifying the nested address object via the cloned person
        clonedPerson.address.city = "New Delhi";

        // Checking if original object's address was affected
        System.out.println("Original Person City: " + person.address.city);
        System.out.println("Cloned Person City:   " + clonedPerson.address.city);
    }
}
```

### Output

```
Original Person City: New Delhi
Cloned Person City:   New Delhi
```

### Code Breakdown

- `@Override Annotation`: Confirms we are overriding the `clone()` method inherited from `java.lang.Object`.
- `implements Cloneable`: Authorizes the JVM to execute `super.clone()`.
- `throws CloneNotSupportedException`: Declared in case the class or superclass does not implement `Cloneable`.
- `super.clone()`: Performs the native shallow copy:
  - `name` is copied.
  - `address` reference is copied as a pointer. Both `person.address` and `clonedPerson.address` point to the same memory block.
- **Limitation:** Changing `clonedPerson.address.city` altered `person.address.city`.

## 2. Deep Cloning

### Definition

**Deep cloning** creates a completely independent copy of the original object **and all nested objects** recursively down the object graph. 

Because the default `Object.clone()` only performs a shallow copy, deep cloning requires **explicitly cloning or recreating all reference-type fields** during the cloning process.

### Deep Cloning Example

```java
import java.util.*;

// Address class (Now implements Cloneable)
class Address implements Cloneable {
    String city;

    // Constructor
    Address(String city) {
        this.city = city;
    }

    // Overriding clone() for Address
    @Override
    protected Object clone() throws CloneNotSupportedException {
        return new Address(this.city); // Creates a new Address object
    }
}

// Person class (Implements Cloneable with Deep Copy logic)
class Person implements Cloneable {
    String name;
    Address address;

    // Constructor
    Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    // Overriding clone() for Deep Cloning
    @Override
    protected Object clone() throws CloneNotSupportedException {
        // Step 1: Perform shallow copy of Person
        Person clonedPerson = (Person) super.clone();

        // Step 2: Explicitly clone the nested Address object (Deep Copy)
        clonedPerson.address = (Address) this.address.clone();

        return clonedPerson;
    }
}

class Main {
    public static void main(String[] args) throws CloneNotSupportedException {
        Address address = new Address("Mumbai");
        Person person = new Person("Rahul", address);

        // Deep Cloning
        Person clonedPerson = (Person) person.clone();

        // Modifying the address in the cloned object only
        clonedPerson.address.city = "New Delhi";

        // Verification: Original remains unchanged
        System.out.println("Original Person City: " + person.address.city);       // Mumbai
        System.out.println("Cloned Person City:   " + clonedPerson.address.city); // New Delhi
    }
}
```

### Output

```
Original Person City: Mumbai
Cloned Person City:   New Delhi
```

### Code Breakdown

- **`Address implements Cloneable`:** Allows `Address` to safely provide its own `clone()` implementation.
- **`clonedPerson.address = (Address) this.address.clone();`:** Disconnects the shared reference by replacing it with an entirely new `Address` object holding identical data.
- **Result:** Modifying `clonedPerson.address.city` does **not** affect `person.address.city`.

> [!IMPORTANT]
> **Why is overriding `clone()` in nested classes required?**
> If `Address` does not implement `Cloneable` and override `clone()`, attempting `address.clone()` will fail with a `CloneNotSupportedException`. Deep cloning requires every mutable class in the object hierarchy to participate in the cloning process.

## Shallow Cloning vs Deep Cloning

| Aspect | Shallow Cloning | Deep Cloning |
| :--- | :--- | :--- |
| **Primitive Fields** | Copied by value | Copied by value |
| **Object References** | Copied by reference (shared instances) | Copied by creating brand new instances |
| **Implementation Complexity** | Simple (just call `super.clone()`) | Higher (must clone all nested objects manually) |
| **Nested Object Independence** | ❌ Dependent (shared) | ✅ Completely independent |
| **Performance** | Faster & less memory overhead | Slower & allocates more memory |
| **Use Case** | Objects containing only primitives or immutable fields (e.g., `String`) | Objects containing mutable nested objects |

## Modern Alternatives to Java `clone()`

While `clone()` is built into Java, it has well-known design flaws (such as bypassing constructors and relying on casting and checked exceptions). Modern Java applications often prefer these cleaner alternatives:

### 1. Copy Constructors (Recommended)

A constructor that takes another instance of the same class and initializes a new object with its values:

```java
class Address {
    String city;

    Address(String city) {
        this.city = city;
    }

    // Copy Constructor
    Address(Address other) {
        this.city = other.city;
    }
}

class Person {
    String name;
    Address address;

    Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    // Copy Constructor for Deep Copy
    Person(Person other) {
        this.name = other.name;
        this.address = new Address(other.address); // Creates independent copy
    }
}
```

### 2. Static Factory Methods

```java
class Person {
    // ... fields and constructors ...

    public static Person newInstance(Person original) {
        return new Person(original.name, new Address(original.address.city));
    }
}
```

## Summary

| Concept | Description |
| :--- | :--- |
| **Object Cloning** | Generating a duplicate object in a new memory address with the same state |
| **`Cloneable`** | Marker interface indicating that `Object.clone()` may be legally invoked |
| **`clone()` Method** | Protected method in `Object` that performs a native shallow copy by default |
| **Shallow Copy** | Copies primitives; shares references to nested objects |
| **Deep Copy** | Copies primitives and recursively creates new instances of all nested objects |
| **Best Practice** | Use copy constructors or static copy methods for safer and more flexible cloning |
