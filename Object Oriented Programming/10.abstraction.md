# Abstraction in Java

Abstraction is one of the fundamental concepts of Object-Oriented Programming (OOP). It is the process of **hiding the implementation details** and showing only the necessary features or interface to the user. In simpler terms, abstraction allows us to focus on **what** an object does, rather than **how** it does it.

Abstraction is achieved through **abstract classes** and **interfaces** in Java. It allows programmers to create a blueprint or template for objects without having to worry about their specific implementation details, making the system easier to use and manage.

## Key Features of Abstraction

- **Hiding Implementation Details:** The goal of abstraction is to hide complex implementation details and provide a simpler interface for interaction. For example, when you drive a car, you don't need to know how the engine works internally — you just need to know how to start, steer, and stop it.
- **Abstract Methods:** Methods declared in abstract classes or interfaces that have **no body**. The implementation must be provided by the subclass or implementing class.
- **Concrete Methods:** Methods with a complete implementation in an abstract class. Subclasses inherit these methods but may also override them if necessary.

---

## Benefits of Abstraction

- **Simplify the system:** By hiding unnecessary details, it reduces complexity.
- **Improve maintainability:** Changes to implementation details don't affect the rest of the system.
- **Increase reusability:** Code can be reused across different parts of the system with different implementations.
- **Provide security:** Users interact with the system at a higher level, without the risk of modifying internal mechanisms directly.

## Methods of Achieving Abstraction

In Java, abstraction can be implemented using:

1. **Abstract Classes**
2. **Interfaces**

## 1. Abstract Classes

An abstract class is a class that **cannot be instantiated** on its own and must be inherited by a subclass. It can have both:
- **Abstract methods** — declared but not implemented (subclass must provide the implementation)
- **Concrete methods** — fully implemented (inherited by subclasses)

```java
import java.util.*;

// Abstract class
abstract class Animal {
    // Concrete method
    void eat() {
        System.out.println("This animal eats food.");
    }

    // Abstract method (no implementation)
    abstract void sound();
}

// Concrete class that extends the abstract class
class Dog extends Animal {
    // Providing implementation for the abstract method
    @Override
    void sound() {
        System.out.println("The dog barks.");
    }
}

class Cat extends Animal {
    // Providing implementation for the abstract method
    @Override
    void sound() {
        System.out.println("The cat meows.");
    }
}

class Main {
    public static void main(String[] args) {
        Animal myDog = new Dog();
        Animal myCat = new Cat();

        myDog.eat();   // Inherited concrete method
        myDog.sound(); // Overridden method in Dog class

        myCat.eat();   // Inherited concrete method
        myCat.sound(); // Overridden method in Cat class
    }
}
```

**Explanation:**
- The `Animal` class is abstract and defines both an abstract method `sound()` (no body) and a concrete method `eat()` (with a body).
- The `Dog` and `Cat` classes are concrete classes that extend `Animal` and provide their own implementations of the abstract `sound()` method.
- When objects of `Dog` and `Cat` are created, both the inherited `eat()` and the overridden `sound()` methods can be called.

## 2. Interface

An interface is similar to an abstract class, but it can only contain **abstract methods** (prior to Java 8). All methods in an interface are implicitly abstract, and it represents a **contract** that implementing classes must fulfill.

```java
import java.util.*;

// Interface
interface Animal {
    void sound(); // Abstract method
    void eat();   // Abstract method
}

// Implementing the interface in the Dog class
class Dog implements Animal {
    @Override
    public void sound() {
        System.out.println("The dog barks.");
    }

    @Override
    public void eat() {
        System.out.println("The dog eats food.");
    }
}

class Main {
    public static void main(String[] args) {
        Animal myDog = new Dog();
        myDog.eat();   // Implemented method
        myDog.sound(); // Implemented method
    }
}
```

**Explanation:**
- The `Animal` interface defines two abstract methods: `sound()` and `eat()`.
- The `Dog` class `implements` the `Animal` interface and provides concrete implementations for both methods.
- When an object of `Dog` is created, both `eat()` and `sound()` can be called.

## Static and Default Methods

Java 8 introduced two important additions to interfaces: **static methods** and **default methods**.

### 1. Static Method

Static methods belong to the **class itself**, not to any instance. They can be called without creating an object. Static methods can only access other static members of the class.

```java
import java.util.*;

class Example {
    static void staticMethod() {
        System.out.println("This is a static method.");
    }
}

class Main {
    public static void main(String[] args) {
        Example.staticMethod(); // Called directly on the class, no object needed
    }
}
```

**Keypoints:**
- Called on the class itself, not on an instance.
- Can be used for operations common to all instances of a class.
- Can only access other **static** members (variables, methods).
- **Cannot** access instance variables or methods.

---

### 2. Default Method

Default methods were introduced in **Java 8** to allow adding new functionality to interfaces without breaking existing implementations. Prior to Java 8, interfaces could only declare method signatures. With default methods, interfaces can now provide a default implementation.

```java
import java.util.*;

interface Example {
    default void defaultMethod() {
        System.out.println("This is a default method.");
    }
}

class Demo implements Example {
    public static void main(String[] args) {
        Example obj = new Demo();
        obj.defaultMethod(); // Accessing default method
    }
}
```

**Keypoints:**
- Defined using the `default` keyword inside an interface.
- Have a body and can be called on objects that implement the interface.
- Allow adding new methods to an interface **without affecting existing implementing classes**.
- Implementing classes can **override** the default method if needed.

**Why were Default Methods Introduced?**

Before Java 8, adding a new method to an interface would **break all existing implementations** of that interface. This was a significant limitation when evolving libraries and APIs without breaking backward compatibility. Default methods solved this by allowing interfaces to provide method implementations alongside their declarations.

**Use Cases for Default Methods:**
- **Backward compatibility:** Add new methods to interfaces without breaking existing classes.
- **Multiple interfaces:** When a class implements multiple interfaces with the same method signature, a default method can provide a fallback implementation to avoid conflicts.

## Abstract Class vs Interface

| Feature | Abstract Class | Interface |
| :--- | :--- | :--- |
| **Instantiation** | Cannot be instantiated | Cannot be instantiated |
| **Methods** | Can have both abstract and concrete methods | All methods abstract by default (default/static since Java 8) |
| **Variables** | Can have instance variables | Only `public static final` constants |
| **Constructor** | Can have a constructor | Cannot have a constructor |
| **Inheritance** | `extends` (single inheritance only) | `implements` (multiple interfaces allowed) |
| **Access Modifiers** | Methods can have any access modifier | Methods are `public` by default |
| **Use When** | Sharing common code among closely related classes | Defining a contract for unrelated classes |

## Important Questions

### Can an abstract class extend another abstract class?

**Yes.** An abstract class can extend another abstract class just like a regular class would. The child abstract class inherits the abstract methods and behaviors of the parent class but is **not required** to implement the parent's abstract methods. If the subclass is also abstract, it can either:
- Implement the abstract methods from the parent class, or
- Leave them unimplemented (the subclass must also be declared `abstract` in this case).

---

### Can an abstract class have a constructor and can we create an instance of it?

**No**, you cannot create an instance of an abstract class directly in Java. An abstract class is designed to be inherited — not instantiated on its own.

**However**, an abstract class **can** have a constructor. It is called when a subclass object is created, allowing the abstract class to initialize its fields before the subclass adds its own behavior.

```java
abstract class Shape {
    String color;

    // Constructor of the abstract class
    Shape(String color) {
        this.color = color;
        System.out.println("Shape created with color: " + color);
    }

    abstract double area();
}

class Circle extends Shape {
    double radius;

    Circle(String color, double radius) {
        super(color); // Calls the abstract class constructor
        this.radius = radius;
    }

    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}

class Main {
    public static void main(String[] args) {
        Circle c = new Circle("Red", 5.0);
        System.out.println("Area: " + c.area());
    }
}
```

**Keypoints:**
- An abstract class **can** have constructors, but you cannot use `new AbstractClass()` directly.
- The constructor is only called when a **subclass** object is created.
- Subclass constructors can call the abstract class constructor using the `super()` keyword.

## Summary

| Concept | Description |
| :--- | :--- |
| **Abstraction** | Hiding implementation details; showing only what's necessary |
| **Abstract Class** | Cannot be instantiated; can have abstract + concrete methods |
| **Abstract Method** | Declared without a body; must be implemented by subclasses |
| **Interface** | A pure contract; all methods abstract by default |
| **Default Method** | Interface method with a body (Java 8+); ensures backward compatibility |
| **Static Method** | Belongs to the class; called without an object |
