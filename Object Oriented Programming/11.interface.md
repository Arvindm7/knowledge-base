# Interface in Java

An interface in Java is a **blueprint of a class** that defines a contract for behavior but does not provide an implementation. It contains a set of abstract methods (methods without a body) that a class must implement if it chooses to "sign the contract" by implementing the interface. Think of it as a way to specify **what** a class should do without dictating **how** it should do it.

By the end of this chapter, you'll understand:

- Interface Inheritance — how interfaces can extend other interfaces

## Basic Example

```java
import java.util.*;

interface Animal {
    void eat();
    void sleep();
}

class Dog implements Animal {
    @Override
    public void eat() {
        System.out.println("Dog eats bones.");
    }

    @Override
    public void sleep() {
        System.out.println("Dog sleeps in a kennel.");
    }
}
```

Here, `Animal` is the interface, and `Dog` is a class implementing it by providing specific behaviors for the `eat` and `sleep` methods.

## Can an Interface Have Instance Variables?

**No.** All fields in an interface are implicitly `public`, `static`, and `final`. This means they act as **constants** and cannot be changed. Attempting to declare a non-static or non-final field will result in a compilation error.

```java
interface Config {
    int MAX_SPEED = 120; // implicitly: public static final int MAX_SPEED = 120;
}
```

---

## Can Interfaces Have Constructors?

**No.** Interfaces cannot have constructors because:
- Constructors are used to initialize the state of an object.
- Interfaces cannot have instance state (no instance variables).
- Interfaces cannot be instantiated directly.

However, a class that **implements** an interface can have its own constructors to initialize its objects.

```java
import java.util.*;

interface Vehicle {
    void start();
}

class Car implements Vehicle {
    private String brand;

    Car(String brand) {
        this.brand = brand;
    }

    @Override
    public void start() {
        System.out.println(brand + " car is starting.");
    }
}
```

In the example above, the `Car` class has a constructor for initialization, but the `Vehicle` interface does not.

## Can a Class Implement Multiple Interfaces?

**Yes.** A class in Java can implement multiple interfaces. This is one of the key advantages of interfaces — Java does not support multiple inheritance with classes, but it does with interfaces.

```java
import java.util.*;

interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

class Duck implements Flyable, Swimmable {
    @Override
    public void fly() {
        System.out.println("Duck is flying.");
    }

    @Override
    public void swim() {
        System.out.println("Duck is swimming.");
    }
}
```

Here, the `Duck` class implements both `Flyable` and `Swimmable` interfaces, providing specific behaviors for flying and swimming.

## Key Features of Interfaces

Interfaces are powerful because they enable several key benefits:

- **Multiple Inheritance:** A class can implement multiple interfaces, combining functionality from various sources.
- **Contracts:** An interface acts as a contract that a class must fulfill, ensuring consistency across different implementing classes.
- **Loosely Coupled Systems:** By programming to an interface rather than a concrete class, your code becomes more flexible and easier to maintain.

Consider the following real-world example:

```java
import java.util.*;

interface PaymentGateway {
    void processPayment(double amount);
}

class PayPal implements PaymentGateway {
    @Override
    public void processPayment(double amount) {
        System.out.println("Processing payment via PayPal: $" + amount);
    }
}

class Stripe implements PaymentGateway {
    @Override
    public void processPayment(double amount) {
        System.out.println("Processing payment via Stripe: $" + amount);
    }
}
```

Here, a client can use any implementation of `PaymentGateway` (e.g., `PayPal` or `Stripe`) without being tightly coupled to a specific one. Swapping payment providers requires no changes to the client code.

## Default and Static Methods in Interfaces

Java 8 introduced **static** and **default** methods to interfaces, enabling more flexibility while maintaining backward compatibility.

### 1. Static Method

Static methods in interfaces belong to the **interface itself**, not to any implementing class. They can be called directly using the interface name without creating an object.

```java
import java.util.*;

interface Example {
    static void staticMethod() {
        System.out.println("This is a static method in an interface.");
    }
}

class Main {
    public static void main(String[] args) {
        Example.staticMethod(); // Called directly using the interface name
    }
}
```

**Keypoints:**
- Called on the **interface itself**, not on an instance of a class implementing the interface.
- Used to perform operations related to the interface itself, not the implementing class.
- Can only access other **static** members of the interface.
- **Cannot** access instance variables or instance methods of the implementing class.

---

### 2. Default Method

Default methods were introduced in **Java 8** to allow adding new functionality to interfaces without breaking existing implementations.

```java
import java.util.*;

interface Example {
    default void defaultMethod() {
        System.out.println("This is a default method.");
    }
}

class Demo implements Example {
    public static void main(String[] args) {
        Example obj = new Demo();
        obj.defaultMethod(); // Accessing the default method
    }
}
```

**Keypoints:**
- Defined using the `default` keyword inside an interface.
- Have a body and can be called on objects that implement the interface.
- Allow adding new methods to an interface **without breaking existing implementing classes**.
- Implementing classes can **override** the default method if needed.

**Why Were Default Methods Introduced?**

Before Java 8, adding a new method to an interface would **break all existing implementations** of that interface — a major limitation when evolving libraries and APIs. Default methods solved this by allowing interfaces to ship a fallback implementation, ensuring existing classes continue to work without modification.

**Use Cases for Default Methods:**
- **Backward compatibility:** Add new methods to an interface without affecting classes that already implement it.
- **Multiple interfaces:** When a class implements multiple interfaces with the same method signature, a default method can provide a fallback to avoid conflicts.

## Interface Inheritance

Interfaces in Java can **extend** other interfaces, allowing for a hierarchy of contracts. When an interface inherits another, it adds new methods to the contract defined by the parent interface.

```java
import java.util.*;

interface Animal {
    void eat();
}

interface Mammal extends Animal {
    void walk();
}

class Human implements Mammal {
    @Override
    public void eat() {
        System.out.println("Human eats food.");
    }

    @Override
    public void walk() {
        System.out.println("Human walks on two legs.");
    }
}
```

Here, the `Mammal` interface inherits the `eat()` method from `Animal` and adds the `walk()` method. The `Human` class then implements **both** methods.

> [!NOTE]
> Unlike classes (which can only `extend` one class), an interface can `extend` **multiple** interfaces at once: `interface C extends A, B { }`.

## Interface vs Abstract Class

| Feature | Interface | Abstract Class |
| :--- | :--- | :--- |
| **Instantiation** | Cannot be instantiated | Cannot be instantiated |
| **Methods** | Abstract by default (default/static since Java 8) | Can have abstract + concrete methods |
| **Variables** | Only `public static final` constants | Can have instance variables |
| **Constructor** | Cannot have a constructor | Can have a constructor |
| **Inheritance** | `implements` (multiple allowed) | `extends` (single only) |
| **Access Modifiers** | Methods are `public` by default | Methods can have any access modifier |
| **Use When** | Defining a contract for unrelated classes | Sharing common code among related classes |

## Summary

| Concept | Description |
| :--- | :--- |
| **Interface** | A blueprint/contract with no implementation (by default) |
| **`implements`** | Keyword used by a class to adopt an interface |
| **Multiple Interfaces** | A class can implement more than one interface |
| **Instance Variables** | Not allowed; only `public static final` constants |
| **Constructors** | Not allowed in interfaces |
| **Static Method** | Belongs to the interface; called via interface name |
| **Default Method** | Provides a default body in an interface (Java 8+) |
| **Interface Inheritance** | An interface can `extend` one or more interfaces |
